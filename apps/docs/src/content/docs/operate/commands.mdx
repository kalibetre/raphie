The `raphie` command starts Raphie, checks it, manages the administrator and handles updates. The user install and source checkout share one CLI; the Linux system service wraps it with extra administration commands that need `sudo`.

| Install        | How you run it                                                    |
| -------------- | ----------------------------------------------------------------- |
| User install   | `raphie <command>` (from `~/.local/bin`)                          |
| System service | `sudo raphie <command>` (only `raphie port` works without `sudo`) |
| Source         | `bun run raphie <command>` from the checkout                      |

Run `raphie --help` for the installed version's summary, and `sudo raphie <command> --help` on the system service for per-command details.

## Lifecycle

| Command          | Installs     | What it does                                                                                                                                                                      |
| ---------------- | ------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `raphie start`   | User, source | Start the runtime and web host in the foreground. `Ctrl+C` stops both. Use it when no background service runs. From source it runs `bun run start`, so run `bun run build` first. |
| `raphie stop`    | User         | Stop the background service and wait until its web and runtime ports are free. It starts again at your next login, or with `raphie restart`.                                      |
| `raphie restart` | User         | Restart the background service, or start it if it was stopped, and wait up to 15 seconds for Raphie to answer.                                                                    |

The system service is managed with `sudo systemctl start|stop|restart raphie`.

See [service](/operate/service/) for logs and the full set of service commands.

## Status

| Command            | Installs     | What it does                                                                                                                                 |
| ------------------ | ------------ | -------------------------------------------------------------------------------------------------------------------------------------------- |
| `raphie status`    | All          | Check the runtime on loopback. Prints its data directory and workspace ID; exits `1` if it does not answer within 3 seconds.                 |
| `raphie health`    | All          | Check both the runtime and the web host. Silent; exits `0` when healthy, `1` otherwise. A locked web host (no administrator yet) is healthy. |
| `raphie port`      | All          | User install and source: print the web address and runtime port. System service: print the web port; works without `sudo` while it runs.     |
| `raphie --version` | User, source | Print the installed release, such as `raphie v0.0.5`. From source it prints `raphie development`.                                            |

## Administrator

| Command               | Installs | What it does                                                                                    |
| --------------------- | -------- | ----------------------------------------------------------------------------------------------- |
| `raphie auth setup`   | All      | Create the single administrator. Prompts for email and password; refuses if one already exists. |
| `raphie auth recover` | All      | Set a new password, sign out every browser and device, and remove all passkeys.                 |

Both need an interactive terminal and must run as the account that owns the data directory. On the system service, `sudo` runs them as the `raphie` service user for you. See [authentication](/operate/authentication/).

## Updates and release channels

| Command                                                                  | Installs | What it does                                                                                                                     |
| ------------------------------------------------------------------------ | -------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `raphie channel`                                                         | User     | Show the release channel.                                                                                                        |
| `raphie channel stable\|nightly`                                         | User     | Change the channel. Takes effect at the next update.                                                                             |
| `raphie update`                                                          | User     | Update to the newest release on your channel, by running the installer from `main`.                                              |
| `raphie update --channel stable\|nightly`                                | User     | Switch channel and update in one step.                                                                                           |
| `sudo raphie update`                                                     | System   | Update to the latest stable release. Nightly releases are not accepted.                                                          |
| `sudo raphie update vX.Y.Z`                                              | System   | Update to an explicit version, including `vX.Y.Z-alpha.N`.                                                                       |
| `sudo raphie update /path/to/bundle`                                     | System   | Update from a trusted local bundle directory.                                                                                    |
| `sudo raphie restore BACKUP`                                             | System   | Restore a backup from `/var/backups/raphie/` and switch to its matching release. Asks you to type `RESTORE`.                     |
| `sudo raphie restore BACKUP --recovery-key FILE --identity AGE_IDENTITY` | System   | Restore on a different host using an exported recovery key.                                                                      |
| `sudo raphie recovery-key export RECIPIENT FILE`                         | System   | Export the keyring unlock credential, encrypted to an `age` recipient, for cross-host recovery. Needs `age` installed.           |
| `sudo raphie uninstall`                                                  | System   | Remove the service and programs; keep data, configuration, keyrings, backups and the service user. Asks you to type `UNINSTALL`. |
| `sudo raphie uninstall --purge`                                          | System   | Also delete data, configuration, keyrings, backups and the service user. Asks you to type `PURGE`.                               |

`raphie update` runs the same installer as the install command, so an update checks the release, backs up the data and restarts the service as described in [updates](/operate/service/#updates-and-release-channels). `sudo raphie update` does not compare versions, so check the target before updating: running older binaries against newer data is unsafe. It checks the download against the release's `SHA256SUMS` but not its attestation; see [check a release by hand](/start/installation/#check-a-release-by-hand). `sudo raphie restore` needs the backup's matching release still under `/opt/raphie/releases/`.

## Ports and origins

| Command                                   | Installs | What it does                                                                                                                   |
| ----------------------------------------- | -------- | ------------------------------------------------------------------------------------------------------------------------------ |
| `raphie set-port WEB_PORT`                | User     | Change the web port, keeping the runtime port. Ports are 1024 to 65535 and must differ.                                        |
| `raphie set-port WEB_PORT --runtime PORT` | User     | Change both ports.                                                                                                             |
| `sudo raphie set-port PORT`               | System   | Change the local web port (1024 to 65535, not `4316`) and restart. Rolls back if Raphie is not healthy within 15 seconds.      |
| `sudo raphie origins`                     | System   | Show the primary, local and additional browser origins.                                                                        |
| `sudo raphie set-origins "A,B"`           | System   | Replace the additional origins and restart. `""` clears them; primary and local origins stay. Rolls back if the restart fails. |

On a user install, `raphie set-port` checks the new ports are free (its own current ports count as free), saves them to `~/.local/lib/raphie/.ports`, restarts the background service and waits up to 15 seconds for it to answer. If it does not, the old ports are put back and the service restarted on them. With no service running, the new ports apply the next time Raphie starts. Afterwards, update anything that points at the old web port, such as `tailscale serve` or the desktop app. See [ports](/start/installation/#ports).

A user install and a source checkout set extra origins through `RAPHIE_WEB_ALLOWED_ORIGINS` in the environment Raphie starts with; see [remote access](/operate/remote-access/#add-an-origin).

Origins are exact, lowercase, with scheme and any non-default port, and no path. Non-loopback origins must be HTTPS. See [remote access](/operate/remote-access/).

## Data directory

| Flag or variable  | Applies to      | What it does                                                                                                                              |
| ----------------- | --------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| `--data-dir PATH` | `start`, `auth` | Use this data directory. Relative paths resolve against the current directory. Give it once.                                              |
| `DATA_DIRECTORY`  | All             | Same, from the environment. Must be absolute for installed binaries; in a source checkout a relative value resolves against the checkout. |

Pass the same directory to `auth` commands that the running Raphie uses, or the account lands somewhere the web host never reads. Default locations are listed in [backup and recovery](/operate/backup-and-recovery/#where-data-lives).

## Environment

The CLI reads these when checking or configuring a running Raphie. The background services set them for you. On a user install the `raphie` command always uses the saved ports, whatever `PORT` and `RAPHIE_WEB_PORT` say, and sets `RAPHIE_WEB_ORIGIN` to `http://127.0.0.1:WEB_PORT`.

| Variable                     | Default (source checkout) | Used by                                            |
| ---------------------------- | ------------------------- | -------------------------------------------------- |
| `PORT`                       | `4316`                    | Runtime port for `status`, `health` and `port`     |
| `RAPHIE_WEB_PORT`            | `4320`                    | Web port for `health` and `port`                   |
| `RAPHIE_WEB_ORIGIN`          | `http://127.0.0.1:4320`   | Primary browser origin                             |
| `RAPHIE_WEB_ALLOWED_ORIGINS` | empty                     | Extra browser origins, comma-separated             |
| `RAPHIE_CREDENTIAL_KEY_FILE` | unset (OS store)          | Headless master-key file path, read by the runtime |

## Installer flags

The user installer (`scripts/install.sh`) takes:

| Flag                        | What it does                                                                                                   |
| --------------------------- | -------------------------------------------------------------------------------------------------------------- |
| `--channel stable\|nightly` | Install or switch to this channel. Default: the saved channel, else `stable`.                                  |
| `--port WEB_PORT`           | Web port for a new install. Default `24320`. Refused on an existing install.                                   |
| `--runtime-port PORT`       | Runtime port for a new install. Default `24316`. Refused on an existing install.                               |
| `--headless`                | Linux only, with a systemd user manager. Use an owner-only master-key file instead of the OS credential store. |
| `--no-modify-path`          | Do not edit shell startup files.                                                                               |

The system installer (`bootstrap.sh`) takes an optional version, `--web-port`, `--web-origin` and `--data-dir`; see [installation](/start/installation/).
