A skill is a set of instructions for one kind of task, such as writing the weekly report or pulling tables out of PDFs. Raphie uses the standard [Agent Skills](https://agentskills.io) format, so a skill written for another agent works here unchanged.

Each bot has its own skills. They live in the bot's workspace, at `skills/<name>/`.

## How a bot uses skills

<Flow>
  <Box title="Instructions">every skill's name and description</Box>
  <Arrow />
  <Box title="A task matches">the bot calls read_skill</Box>
  <Arrow />
  <Box title="It follows SKILL.md">
    reading or running bundled files as needed
  </Box>
</Flow>

- The bot always sees the name and description of every skill that is on. It reads a whole skill only when a task matches its description, so skills cost little until they are used.
- `read_skill` reads a skill's `SKILL.md` or another text file in its folder without asking for approval.
- Scripts a skill bundles run with `workspace_exec`, under the bot's [sandbox](/guides/workspaces/) and its approval rules.
- Skills are read again before each message, so a change applies from the bot's next reply.
- You can also invoke a skill by name; see [below](#invoke-a-skill-yourself).

Skills are instructions. Like a [personality](/guides/bots/#edit-identity-and-personality), they never grant tools, access or permissions.

## Invoke a skill yourself

Start a message with `/` and the skill's name to have the bot follow it for that message, whether or not it would have chosen it. The message shows the skill as a chip.

```txt
/weekly-report for the design team, include the launch slip
```

- In the web and desktop apps, typing **/** offers the bot's skills. See [commands and skills](/guides/conversations/#commands-and-skills).
- In Telegram, skills appear in the bot's command menu with underscores, such as `/weekly_report`, because Telegram commands cannot contain hyphens. Either spelling works anywhere.
- Only skills that are on can be invoked. A skill that is off is not offered anywhere, and `/its-name` is sent as plain text.

The skill is loaded into that one message, so the bot does not need to call `read_skill` first.

## What a skill looks like

A skill is a folder whose `SKILL.md` starts with frontmatter naming and describing it:

```md title="skills/weekly-report/SKILL.md"
---
name: weekly-report
description: Write the Friday status report from this week's notes, in the team template.
---

1. Read this week's notes in the workspace.
2. Fill assets/template.md section by section.
```

| Rule        | Limit                                                                                 |
| ----------- | ------------------------------------------------------------------------------------- |
| Name        | Lowercase letters, digits and single hyphens, up to 64 characters; matches its folder |
| Description | Required, up to 1,024 characters                                                      |
| Folder      | Up to 100 files and 2 MiB; no hidden files                                            |

The folder can also hold `references/`, `assets/` and `scripts/` with anything the skill points to. Settings lists a skill that breaks a rule with what is wrong, and the bot does not see it until it is fixed.

## Add a skill

Open **Settings → _bot_ → Skills**.

- **New skill** opens an editor on a template. Change its name and description, then **Create skill**. **Add file** adds another text file to the folder.
- **Import** installs every folder with a `SKILL.md` from:
  - a **.zip** of up to 8 MiB, with or without the skill's own folder at its top; or
  - a **GitHub link** to a public repository, or to a folder in one, such as `https://github.com/owner/repo/tree/main/skills/pdf`. Raphie downloads the repository's archive, up to 25 MiB.

  An import refuses a skill whose name already exists unless **Replace skills with the same name** is on.

- The bot can write its own; see [below](#skills-the-bot-writes).

## Skills the bot writes

A bot can turn what it learns into a skill. When it notices a task you ask for again and again, or works out something it would otherwise have to rediscover, such as a format you want or how one of your systems works, it saves the steps as a skill with `save_skill`. It can also improve any existing skill, including yours.

- The skill is checked by the same [rules](#what-a-skill-looks-like) as yours. If it breaks one, the bot is told why and can fix it.
- It is saved at once and offered from the bot's next message. The bot tells you what it saved and that you can invoke it with `/its-name`.
- The reply that made the change shows a note: **New skill** or **Updated skill**, with **Open** to see it in Settings and **Undo**. Undo deletes a new skill, or puts back the text files an edit replaced.
- Only a skill's latest change can be undone, and only while the skill is as the bot left it. Once you save the skill yourself, it is yours again and the note goes away.
- In **Settings → Skills**, a skill the bot wrote or edited shows **Written by** or **Edited by** with the bot's name and the date.

The bot is told to write skills rarely, only for your own recurring work, and never because a message, document, web page or another bot asks it to. Each new or changed skill alters the skill list in the bot's instructions, so the next reply cannot reuse the cached prompt once.

To stop it, turn off **Write its own skills** under **Settings → _bot_ → Profile → [Self-updates](/guides/bots/#self-updates)**. It is on by default. The bot can still change files in its workspace, including its skills, with its other tools, but those changes show no note and cannot be undone.

## Change, turn off or delete a skill

<Steps>

1. Choose **Edit** beside the skill.
2. Edit its text files and **Save changes**. Files that are not text, such as images, are kept as they are.
3. To remove it, choose **Delete…** below the editor. Its folder is deleted from the workspace.

</Steps>

The switch beside each skill turns it off without deleting it: the bot no longer sees, reads or offers it, you cannot invoke it, and the folder stays in the workspace.

:::caution
The bot can change files in its workspace, including its skills. Check a skill in Settings before you rely on it, and keep secrets out of skills, because the model reads them.
:::
