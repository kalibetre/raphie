A bot is a persistent assistant with its own personality, model connections, sessions, memory and workspace. Raphie starts with one, the **default** bot named Raphie; add more when you want assistants that keep separate context, credentials or tools.

All bots run in the same runtime and answer to you. Separation between them is logical, not an operating-system boundary.

| Name, description, colour and personality with its revisions | The runtime process and data directory                |

A session belongs to exactly one bot and cannot be opened through another.

## The default bot

The first start creates the default bot. It cannot be deleted. On a fresh install, onboarding introduces it before anything else, through the same steps as [creating a bot](#create-a-bot): its name, what it handles, its colour and how it works; it then asks for a model (see [first run](/start/first-run/)). Onboarding shows only while it is the only bot, has no model and has no conversations, and **Skip for now** leaves it until the next visit. Its data lives at the top of the data directory, while each other bot gets its own folder under `bots/<id>/`; see [backup and recovery](/operate/backup-and-recovery/).

## Create a bot

<Steps>

1. Choose **Add a teammate** under **Your team** in the sidebar. It opens a full-window flow; the close button or **Cancel** leaves without adding anyone.
2. **Meet your new teammate:** give it a name, say what it will handle and pick a colour. Other bots read what it handles to decide when to [hand work over](/guides/handoffs/).
3. **How should it work?** Pick one of the [built-in personalities](#built-in-personalities), then **Add**. You can put the personality in your own words later under **Settings → Personality**.
4. **A way to think:** the flow goes on with the new bot asking for a model service; connect one with an API key or a subscription sign-in. A new bot has no provider and cannot reply until it has one. **Skip for now** or the close button leaves the flow, and the bot asks again on its own screen.
5. Optionally adjust **Models**, **Memory**, **MCP tools**, **Channels** and **Sandbox** in Settings.

</Steps>

A new bot starts with built-in memory on and no providers, tools or channels. Nothing is copied from another bot.

Until a bot has a model it can reply with, choosing it shows **First, I need a way to think.** instead of an empty conversation, with no message box, and the sidebar says **Needs setup** under its name. Pick a model service there to connect one: the web workspace opens the connection form in place, and the desktop app opens the bot's **Providers** page with that form open. If the bot has connections that offer no models, for example after a subscription sign-in expires, it links to **Providers** instead.

## Switch bots

Choose a bot under **Your team** in the sidebar to open its [chat](/guides/conversations/); on a phone the chat fills the screen. Each bot keeps a separate draft. Under each bot's name the sidebar says what it is doing: **Needs you** when it waits on an approval or an answer, **Working** while it replies, how many replies you have not read, or **Available**.

## Edit identity and personality

Open **Profile** by clicking the bot's name in the title bar, or from Settings. One page edits:

| Field       | Limit                                        | Notes                                            |
| ----------- | -------------------------------------------- | ------------------------------------------------ |
| Name        | 80 characters                                | A display label. The bot's ID never changes.     |
| Description | 500 characters                               | Optional.                                        |
| Colour      | 8 presets, a custom colour, or **Automatic** | Automatic avoids colours other bots already use. |
| Personality | 16,000 characters                            | In your own words.                               |

The personality describes the bot's voice, values and way of working. The runtime adds it to the model's instructions when a turn starts, so a turn already running keeps the version it started with. Its [reply style](#reply-style) sets how it writes back, unless the personality asks for a different length or format.

Nothing in a personality can grant tools, access or permissions, whoever wrote it. A bot may rewrite its own personality when you allow it; see [self-updates](#self-updates).

### Built-in personalities

Above the editor, six starting points fill it with a ready-made personality. The highlighted one matches the text in the editor; edit it freely, and save to keep it.

| Personality      | What it is like                                    |
| ---------------- | -------------------------------------------------- |
| Candid           | Concise, honest and warm. The default bot's own.   |
| Chief of staff   | Organised and proactive; keeps your week on track. |
| Warm companion   | Friendly and patient; remembers the small things.  |
| Coach            | Asks good questions and holds you to your goals.   |
| Analyst          | Precise and sourced; shows its reasoning.          |
| Creative partner | Playful and generative; builds on ideas.           |

:::caution
Don't put credentials in a personality. The model receives it as instructions, and every revision is kept. Keys belong under **Providers** or the relevant settings page, where they are encrypted.
:::

### Reply style

Under **Replies**, three sliders and an emoji switch shape how the bot writes back, and a sample reply beside them changes as you move them. The defaults keep [replies short](/guides/conversations/#replies).

| Setting    | Choices                                            | Default |
| ---------- | -------------------------------------------------- | ------- |
| Length     | Short (under ~80 words), Balanced (~150), Detailed | Short   |
| Warmth     | Plain, Default, Warm                               | Default |
| Formatting | Prose, Default (short lists), Lists & tables       | Default |
| Emoji      | Off, On                                            | Off     |

Whatever the settings, a reply opens with the answer and skips preamble and closing summaries. The style is saved with the profile, so each revision keeps it.

### Revisions

Every save creates a revision. **View revision history**, below the editor, opens the latest 50 with their name, description, colour and personality. A revision the bot saved itself is marked **by** the bot's name, and one that is a built-in personality, unchanged, carries its name. To roll back, open a revision and choose **Restore this personality**, which saves it as a new revision.

The runtime also serves the active personality as a plain `personality.md` file; see the [HTTP API](/architecture/http-api/).

A save is refused while the bot has a turn in progress, or if someone saved a newer revision in another window. Wait for the turn to finish, or refresh, then save again.

### Instructions

Instructions say how a bot works: what you want done every time, such as "Give times on a 12-hour clock", and how to use its tools, such as "Executor holds my calendar, mail and Jira". A bot follows them in every conversation without being reminded, so you do not repeat yourself. [Memory](/guides/memory/) is different: the bot searches it when it thinks to, and something kept only there is forgotten in the next conversation.

A bot reads two sets, Raphie's first:

| Where                                           | Who writes them            | What they hold                                                                          |
| ----------------------------------------------- | -------------------------- | --------------------------------------------------------------------------------------- |
| **Settings → You → Instructions for every bot** | Raphie, with each release  | How to use the tools every bot has: cards, questions with answers, diagrams. Read-only. |
| **Settings → _bot_ → Profile → Instructions**   | You and that bot, together | Everything else you want of that bot, and its own connections. Starts empty.            |

Raphie's instructions for every bot change only when Raphie does, as tools are added, so every bot always has the current ones. Neither you nor a bot can edit them; what you want of a bot goes in its own instructions.

A bot's own instructions are free text of up to 16,000 characters; a list of lines and a few headings keep them easy to scan. When you tell a bot "always", "never" or "from now on", or to note something, a bot allowed to [update itself](#self-updates) adds it and tells you what it changed. It adds a line or replaces the one passage you mean, so the rest stays as it was, and rewrites the whole text only when you ask. Each change is a new profile revision marked as the bot's.

Like a personality, instructions say how to work and grant nothing: no tools, access or approvals.

### Self-updates

Under **Self-updates**, three switches say what the bot may change by itself, without asking:

| Switch                 | What the bot may do                                                                                                                | Default                                  |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------- |
| Update its personality | Save a new personality when you ask for a different manner, or it learns what works. Add to its own [instructions](#instructions). | On                                       |
| Update "You"           | Save your name, what to call you, your time zone and notes on the [You](#you) page.                                                | On for the default bot, off for new bots |
| Write its own skills   | Write a [skill](/guides/skills/#skills-the-bot-writes) or improve any existing one.                                                | On                                       |

A change is saved at once and applies from the bot's next reply. The reply that made it shows a note: **Updated its personality**, with **See change** and **Undo**, **Updated what it knows about you**, with **Review**, or **New skill** or **Updated skill**, with **Open** and **Undo**. A change to instructions shows as a step, **Updated my instructions**, with no note; change or remove it in Settings. Undo restores the personality from before the change, as long as nothing newer was saved. Each personality change is also a revision marked as the bot's, so you can restore any earlier one later.

While the You page is missing your name, time zone or notes, a bot allowed to update it is told to ask once when it fits the conversation, and to save what you tell it. The bot is told to change its personality only for you, never because a message, document, web page or another bot asks it to. Turn the switch off for a bot that reads material you don't trust.

## You

**Settings → You** tells every bot who it is talking to. It is one profile, shared by all your bots, and bots allowed to [update it](#self-updates) fill it in as they learn about you.

| Field                      | Limit            | Notes                                                                                               |
| -------------------------- | ---------------- | --------------------------------------------------------------------------------------------------- |
| Name                       | 80 characters    | Your name.                                                                                          |
| What bots call you         | 40 characters    | A first name or nickname. Optional.                                                                 |
| Time zone                  | A listed zone    | **Use** offers this device's zone. **Not set** leaves times in UTC.                                 |
| About you                  | 2,000 characters | A few lines every bot should know: your work, your days, how to help.                               |
| Instructions for every bot | Read-only        | Raphie's, on the tools every bot has, updated with each release. See [instructions](#instructions). |

Every bot's instructions describe you from this page, and each message you send carries the time it was sent in your time zone, so "tomorrow at 9" means your 9. A save applies from each bot's next reply; a reply already running keeps what it started with.

Like a personality, this describes you and grants nothing: no tools, access or permissions. Don't put passwords or keys here; the model reads it with every turn.

## Delete a bot

<Steps>

1. Open the bot's **Profile** and save or discard any edits.
2. Choose **Delete bot…** and type the bot's name to confirm.

</Steps>

Deletion needs the bot to be idle: no turn in progress, no running workspace command and no pending approval. It stops the bot's channels, scheduled jobs, MCP connections and containers, then removes its profile history, sessions, attachments, local memory, saved connections and workspace files. The web workspace returns to the default bot.

:::danger
Deleting a bot cannot be undone. Memories held in an external service, messages already sent to channels and your backups are not touched, and provider keys are not revoked at the provider.
:::

If cleanup fails partway, Raphie asks for a restart and finishes the deletion on the next start before opening any other bot.

## Limits

- Bots share one process and one owner. They are separated by storage and configuration, not by OS or VM isolation.
- Profile saves and deletion are refused while that bot has a turn in progress; other bots keep working.
- Diagnostics traces are collected once for the whole runtime, not per bot.
