The web workspace is the browser app where you talk to your bots. Each bot has one **chat** with you, like a direct message with a teammate: pick the bot in the sidebar, type in the composer, and the reply streams in as the bot works, with its tool steps inline. Approvals and questions that wait on you dock on top of the composer.

The chat is stored by the runtime, not the browser. Closing the tab never cancels work, and the chat is the same in the desktop app and in your private Telegram or Discord chat with the bot.

Its address depends on how you installed Raphie:

| Install                     | Web workspace                                              |
| --------------------------- | ---------------------------------------------------------- |
| User install (macOS, Linux) | `http://127.0.0.1:24320`, or the port you chose at install |
| System service (Linux)      | `http://127.0.0.1:41837`, or the `--web-port` you chose    |
| Source checkout             | `http://127.0.0.1:4320`                                    |

`raphie port` prints the web port of the install on this machine. A user install made before ports were saved keeps `4320`. From another computer, use the `https://` address from [remote access](/operate/remote-access/).

## Your team and the chat

| Where                | What it does                                                                                                                                                                                                                       |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Sidebar, top         | What waits on you, one line per bot: _bot_ **has a question**, **needs your OK**, or **has 3 questions** when several wait. Choose one to open where they wait: the bot's chat, or a group's conversation the chat doesn't cover.  |
| **Your team**        | Your bots, each with what it is doing: **Needs you**, **Needs setup**, **Working**, new replies or **Available**. Choosing one opens its chat. **Add a teammate** opens the flow that [creates a bot](/guides/bots/#create-a-bot). |
| Sidebar, bottom      | Where Raphie runs (**This computer**, or the host's name) and the gear that opens Settings. **Reconnecting…** shows while the connection is down.                                                                                  |
| Notifications (bell) | Replies, approval requests and finished scheduled jobs from every bot in one place.                                                                                                                                                |

On a phone the sidebar is the home screen, at full width. Choosing a bot fills the screen with its chat; the arrow at the top left goes back to your team.

A bot you have not talked to yet opens on its empty desk: **I'm ready when you are.** with four things to ask, such as a morning briefing or research. Choosing one puts the request in the composer to finish and send; nothing is sent until you send it. Your first message starts the chat.

There is no new conversation: you keep talking to the bot in its one chat. When the chat grows long, the bot reads a [summary of earlier messages](#long-chats) in their place.

Read state is shared through the runtime: a reply you read on the desktop app is marked read here too.

### Conversations from before chats

Conversations started before bots had one chat are removed when Raphie starts. The most recent one you started from an app became the bot's chat and stays, as do group and server-channel sessions and tasks another bot handed off. Scheduled jobs' own conversations go too: their runs now post in the chat. A conversation with a reply still in progress waits for a later start.

Before removing anything, Raphie copies the bot's storage to `backups/before-one-chat-<time>.sqlite` in the bot's [data folder](/architecture/state/#what-each-bot-stores). Links to a removed conversation, such as a memory's source or an earlier job run, no longer open it. The copy is for recovering what was in them, not for going back: restoring it into this version removes them again on the next start. If the copy cannot be made, nothing is removed and the bot starts as usual; Activity records why. Raphie never deletes the copies.

## The composer

| Control       | Use                                                                                                                              |
| ------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| Text box      | Up to 4,000 characters. **Enter** sends; **Shift+Enter** adds a line.                                                            |
| Attach files  | Up to four files per message. See [attachments](/guides/attachments/).                                                           |
| Model picker  | The model for this chat. See [choosing a model](#choosing-a-model).                                                              |
| Permissions   | **Ask** (the default) or **Full access** for workspace commands and MCP tools. See [approvals](#tool-approvals).                 |
| Context donut | How full the model's context is. Hover it for the numbers, and the tokens and cost of the chat so far; it turns amber past 80%.  |
| Send / Stop   | Send turns into Stop while the bot is working and the draft is empty. With text in the draft, **Stop task** is under the ⋯ menu. |

### Commands and skills

Type **/** at the start of the draft for a menu of commands and the bot's [skills](/guides/skills/). Arrow keys and **Enter** choose; **Escape** closes it.

| Entry           | Does                                                                        |
| --------------- | --------------------------------------------------------------------------- |
| `/model`        | Opens the model picker                                                      |
| `/stop`         | Stops the reply in progress (only while the bot is working)                 |
| `/handoff`      | Writes `@` so you can choose a bot to [hand the task to](/guides/handoffs/) |
| `/<skill-name>` | Writes `/<skill-name> ` so your message invokes that skill                  |

Commands act at once and send nothing. A `/` later in a message, or a word that matches nothing, is plain text.

You can keep sending while the bot works. A waiting message shows as **Queued**; choose **Steer** to have the bot pick it up after its current tool step, or **Keep queued** to leave it until the current reply finishes.

Stopping withdraws queued messages, marks the interrupted reply as stopped and expires any approval request still waiting in the session. It does not undo anything a tool has already done.

### Quoting a message

To talk about an earlier message, yours or the bot's, point at it and choose **Quote**: it sits under the bot's replies, and beside your own messages (under them on a phone). The quote appears above the composer with the author and how the message starts; **✕** drops it. When you send, your message carries the quote inside it, with a green edge for the bot's words and a grey one for yours. Choosing a quote scrolls to the message it came from, if it is loaded.

A message quotes at most one other. The bot reads the quoted words before your message, so "Shorter, please" next to a quote means that message.

## Choosing a model

The model picker lists models from the providers connected to this bot, with search, family filters and favourites. Favourites are kept in this browser.

- Choosing **before** the first message sets the chat's model.
- Choosing **later** changes the chat's model, while the bot is idle.
- The chat keeps its model across restarts and when you change the bot's default under **Settings → Models**.

If the bot has no provider yet, the workspace prompts you to connect one; see [first run](/start/first-run/).

## Following progress

Replies stream as text with Markdown, code and Mermaid diagrams rendered. Each reply is signed with the bot's avatar, name and time; pointing at the time shows the reply's tokens and cost when the provider supplies them. While a turn runs, tool steps appear in the reply. Once it finishes, they fold into one line under the reply that says what the bot did, such as **Updated a scheduled job, noted something to remember**; expand it to see each tool with its arguments and result.

When a reply cannot finish, the bot says so under your message ("I couldn't finish this reply.") with the reason: for example, that the model returned an error, that no model is chosen, or that the bot used its limit of tool rounds. For a model error, **Details** shows the provider's own message, such as a rate limit; anything shaped like a key is masked. The desktop app shows the same. A channel such as Telegram gets the reason without the provider's message. The **Reply failed** event in Activity records both.

For a fuller record, open **Settings → [bot] → Activity**: the bot's latest 100 events across all sessions (model calls, tools, approvals, recovery), refreshed every five seconds, with JSON export. Model reasoning is never shown. More in [observability](/operate/observability/).

## Replies

By default, bots keep replies short. A reply opens with the answer, or the one question the bot needs answered, in a sentence or two. What follows is only what you need to act on it, as a short list or table rather than paragraphs, and most replies fit in under 80 words. A reply runs longer when you ask for detail or the work is long by nature, such as code or a draft you asked for.

To change this for one bot, set its [reply style](/guides/bots/#reply-style), or say how it should reply in its [personality](/guides/bots/#edit-identity-and-personality); a personality that asks for something else wins. What every bot knows about you, including your time zone, is set under [You](/guides/bots/#you).

## Cards

When the answer is a set of items you will scan, such as a day's events, open tickets or pull requests waiting for your review, a bot shows them as a card under a short reply instead of writing a list.

| Card     | Shows                                                                                                                                                                     |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| List     | Rows, optionally in groups such as a status.                                                                                                                              |
| Timeline | A schedule: the events of one or more days in order, with free time of 30 minutes or more between them. See [Schedules](#schedules).                                      |
| Board    | A project's columns, from Fizzy, Jira, Trello or any tool with boards: a bar and a count for each column, then each column's first 10 tasks, with how many more it holds. |
| Item     | One task or ticket opened up: its facts under labels (status, who has it, due date, tags), the start of its description, and its checklist with the first five steps.     |

A row has a title, and can have a key (`AF-512`), a line of detail, a badge and a short value such as its age. A task can also show who has it as initials (up to four people), its tags, how far its checklist has got, and when it is due. A due date turns amber today and tomorrow, and red once it has passed.

Any card can carry up to four headline numbers, and a line at the bottom for what it leaves out. A list or timeline holds at most 40 rows or events.

A card is never refused for being too long. Text that wraps, such as a title, a line of detail or a warning, keeps up to 300 characters; text drawn beside other things, such as a badge, a tag or a headline number, keeps 16 to 24. Anything longer is cut with an ellipsis.

Cards are laid out for a phone at every width and take the full width of the conversation: a title wraps rather than being cut off, its small parts sit on one line beneath it, and a row is tall enough to press.

- **Links:** a title opens the ticket, pull request or event in your browser, the card's own title opens the board or query it came from, and a row can carry one more link, such as **Join** for a meeting. Only `http` and `https` links are kept.
- **Several accounts:** when a card mixes sources, such as two calendars, each row has its source's colour and the card names them at the top. An event that sits on two calendars shows once, in both colours, and events that share time are badged **Overlaps**.
- **Your days:** events are placed on your days using the time zone under [You](/guides/bots/#you), even when a calendar answers in another zone. Without one, each event stays on the date its calendar gave. An event with no end time is not counted as busy or free.
- **Column colours:** a board's columns take the colour the tool gives them, matched to the nearest of eight named colours and drawn in Raphie's own shade for light and dark. A column with no colour is given one.
- **A missing source:** when the bot could not read one of them, an amber line on the card says which, so a card never looks complete when it is not.
- **As of:** a card is what the bot read at that moment, stamped with the time. It does not update; ask again for a fresh one.

### Schedules

A timeline card is drawn as a schedule. Everything below is worked out by the web workspace and the desktop app from the events' times, so it is the same for a card shown before and stays right as the day goes on.

- **Heading:** a card of one day is headed by that day, such as **Today** under "Monday 23 November", taken from its events rather than the card's title. A card of several days keeps its title and gives each day a heading with its date and number of events.
- **How full it is:** under a one-day heading, the number of events, the time they take with overlaps counted once, and when the day frees up after its last event.
- **The day at a glance:** today has a bar of its busy time with a mark for now, from 8 AM to 6 PM or wider to fit its events. Events that share time are drawn one above the other.
- **All-day events** sit together above the agenda.
- **What is next:** today shows what is on now, or else the next event, with how long until it starts or ends and its **Join** link. It also stays in the agenda below.
- **The agenda:** each event has its start and end in a column, then its title, detail and badge. Today's events that are over fold into one line, such as "2 earlier · Standup, 1:1 with Hana"; press it to show them. A **Now** line marks the present.

Cards are read-only: a checklist shows what is ticked but cannot be ticked. To act on a row, open it, or ask the bot.

A bot working on a task another bot [handed off](/guides/handoffs/) writes the list in its reply instead, because only the reply goes back to the bot that sent the task.

Telegram and Discord cannot draw a card, so there it is added to the reply as a plain list with its links. The web workspace and the desktop app show the same session's card.

:::note
The bot copies links from what its tools returned. Raphie checks that a link is a web address, not that it leads where the row says, so glance at the address before you sign in anywhere.
:::

## Work items

A bot keeps a **work item** for each thing it tracks for you beyond one reply: a request it is still chasing, something it promised to come back to, a decision it waits on from you. A request it settles in the same reply never becomes one.

Each item has a short id such as `w-12`, a title, and a status: **active** while the bot works on it, **waiting** while it is blocked (with what it waits on), and **done** or **dropped** once closed. The bot keeps notes on it and its latest result, and closes it when it is finished or you no longer want it.

- **Asking about them:** ask the bot what is going on, or about one thing by name. It answers from its open items, which it reads with each of your messages, and can read any item in full, closed ones included. Each message carries up to 20 open items: the bot's own come first, then running scheduled jobs, then its other jobs, so many jobs never push out what it is chasing for you.
- **Only in your chat:** work items are yours. A Telegram group or Discord server channel with the bot never sees them, and the bot can't open or change them there. A [scheduled job](/guides/schedules/)'s run happens in the job's own session, so it isn't sent the list, can't use the work tools and doesn't read the chat; what it reads is the job's earlier runs. If its [home channel](/guides/schedules/#send-results-to-a-home-channel) is a group, those runs' replies go there too.
- **Scheduled jobs** are items too, opened when the job is saved and closed when it is removed. Each run happens in the item's session, and its reply posts in the chat as the bot's message, its tab marked **scheduled**; see [Scheduled jobs](/guides/schedules/#how-schedules-work).
- **Handoffs** are items on both sides: a task the bot hands another bot from your chat waits on that bot, and a task it receives runs in its own session; see [Handoffs](/guides/handoffs/#as-work-items).
- **Closed items** are kept, listed apart from open ones.

The bot opens, updates and closes items itself. You can also see and change them under **Settings → Work** for that bot, where open items are in the order the bot sees them, scheduled jobs last: add an item, edit its title and notes, mark it done, drop it, or reopen a closed one. A scheduled job's item changes only with its job, under **Scheduled jobs**, and a handoff's item reopens only when the bot sends a follow-up. The bot reads your changes with your next message.

### Background work

For work that takes a while, such as research, comparing options or drafting something long, the bot can start it in the background instead of in its reply. The work runs in the item's own session, apart from your chat, so the chat stays quick and the item keeps its own context: a follow-up on the same item continues where the last run left off.

- **While it runs:** the item shows **Working** under **Settings → Work**, and you can keep talking to the bot. **Stop** in the chat stops only the chat's reply; **Cancel run** on the item stops its background work.
- **When it ends:** the bot tells you what came back, in a message of its own. Under its name, a tab names the item and quotes the request that started it, with a stamp: **Done**, **Failed** or **Cancelled**. Pressing the tab opens that item under **Settings → Work**. **Quote**, under the message while you point at it, quotes the whole reply. The item keeps the result as its latest.
- **Closing a running item**, on the Work page or by asking the bot, stops its work, and the chat isn't told what came of it; the item still keeps the result.
- **Approvals and questions** from background work dock on the composer with the chat's own, under the work item's title (see [Questions and approvals](#questions-and-approvals)), and the end of the chat marks each one. They also count at the top of the sidebar. This covers every open work item with a session of its own: background runs, scheduled jobs and tasks other bots hand this one.
- An item runs one piece of background work at a time. Its session is kept while the item exists.

## Long chats

A chat can go on as long as you like. Every message you send makes the model read the chat again, so the bot keeps it short: once it grows past a working size, the bot writes notes on its earlier messages and reads those instead of them from then on. Its most recent messages stay word for word.

- **When:** notes start in the background once the chat holds about 64k tokens, whatever the model's context window, or most of a smaller window (about 24k of a 32k one). A reply waits for them only when the chat nearly fills the window (about 184k of a 200k window). If the provider still rejects a request as too long, the bot summarizes and tries again. A model with no known context window is summarized only after such a rejection.
- **What you see:** while a reply waits for a summary, it says **Summarizing earlier messages…**. Afterwards a line above your message reads **Earlier messages summarized**; **View summary** opens what the bot now reads. The desktop app shows the same.
- **What the notes keep:** what the bot promised, open threads, your preferences and decisions, the people and things that came up, exact details such as dates and links, and what the chat was about most recently. Each new set of notes folds in the last, dropping what is finished. If the notes can't be written, the bot falls back to a general summary.
- **What stays:** your transcript keeps every message, tool step and reply. Only the model's context is shortened.
- **What it costs:** the summary is one more call to the chat's model, about the size of the chat, and that turn can't read the earlier messages from the provider's prompt cache.

A summary is a record of what was said, not new instructions. Whatever it says another bot, a tool or the web wrote is still data, and it never grants permissions or approves a tool call.

## Questions and approvals

When a bot needs you to decide something before it can go on, it asks with buttons instead of writing the question out, or asks you to approve a tool call. The turn waits. Everything waiting on you in this chat, the bot's own and its [background work](#background-work)'s, sits in an amber dock on top of the composer, oldest first:

- **The top one** shows who asks (the bot, or the work item's title), **Question** or **Approval**, how many more wait behind it, its work item's id, and its choices. More waiting show as edges behind it.
- **Answering it** brings up the next; when nothing is left the dock goes away.
- **In the chat**, where it was asked, a line says _bot_ **asked you something**, or that a tool step needs your approval. Once you answer, the line becomes a receipt: **You answered** and your answer.
- **At the top of the sidebar** the bot shows as **has a question**, **needs your OK**, or **has 3 questions** when several wait.

A question's choices work like this:

- **Pick an answer** with one press. Answers that carry details, such as a time and a place, show as rows.
- **Answer in your own words** in the message box: while a question is on top of the dock, it says **Or answer in your own words…**, and what you send answers the question instead of going to the chat.
- **Before something that can't be taken back**, such as deleting or sending, the action itself is the red button and the way out sits beside it.

Afterwards the receipt stays in the chat with what you answered. A question waits an hour; after that, or if you stop the turn, the bot goes on without an answer and says what it still needs.

When you wrote from Telegram or Discord, the question also arrives there, with a button per answer. Only you can press them, in the chat you wrote from; once answered, the message shows your answer and loses its buttons. To answer in your own words, use the web workspace or the desktop app. An answer from any of them settles the question everywhere.

A turn started by a schedule, by another bot or in a group chat has nobody to press a button, so there the bot asks in its reply instead.

## Tool approvals

When a bot wants to run something that needs your say-so, the turn pauses and an approval card shows the exact tool and arguments.

| Choice                  | Effect                                                                                                                                                     |
| ----------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Reject**              | The action does not run.                                                                                                                                   |
| **Approve once**        | Runs this exact call once.                                                                                                                                 |
| **Approve for session** | Workspace commands only. Allows the same command with the same arguments again in this chat. Survives restarts; the workspace has no control to revoke it. |

Each card shows when it expires; an expired request cannot be approved. A decision made in any client or channel settles the same request everywhere.

**Permissions** apply to workspace commands and [MCP tools](/guides/tools/). **Full access** lets both run without asking in this chat. It does not change sandbox limits, and an MCP server with approvals of its own still asks for them. Switching back to **Ask** stops calls that have not started yet.

:::caution
An action interrupted by a crash or restart is marked uncertain and is never repeated automatically, because it may already have taken effect. Check the result before asking again.
:::

## UI plugins

UI plugins are small, trusted additions built into the web workspace. The one included is a **token counter** beside the context donut: while you type, a rough estimate for your draft (about one token per four characters). It is hidden on a phone.

Turn plugins on or off under **Settings → UI plugins**. Plugins are not a sandbox or a marketplace, and they grant bots no extra capabilities.

## What stays in your browser

The browser keeps only conveniences; history lives in the runtime.

| Kept in browser storage                 | Scope                  |
| --------------------------------------- | ---------------------- |
| Message drafts and attached-file drafts | Per bot and session    |
| Theme, sidebar width, favourite models  | This browser, all bots |
| Last open session, local read markers   | Per bot                |
| Enabled UI plugins                      | This browser           |

Clearing site data loses unsent drafts and these preferences, never conversations.
