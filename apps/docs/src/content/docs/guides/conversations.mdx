The web workspace is the browser app where you talk to your bots. Pick a bot in the sidebar, type in the composer, and the reply streams in as the bot works; tool steps and approval requests appear inline in the same conversation.

Every conversation is a durable **session** stored by the runtime, not the browser. Closing the tab never cancels work, and the session looks the same from the desktop app or a channel.

Its address depends on how you installed Raphie:

| Install                     | Web workspace                                              |
| --------------------------- | ---------------------------------------------------------- |
| User install (macOS, Linux) | `http://127.0.0.1:24320`, or the port you chose at install |
| System service (Linux)      | `http://127.0.0.1:41837`, or the `--web-port` you chose    |
| Source checkout             | `http://127.0.0.1:4320`                                    |

`raphie port` prints the web port of the install on this machine. A user install made before ports were saved keeps `4320`. From another computer, use the `https://` address from [remote access](/operate/remote-access/).

## Sessions

| Where                   | What it does                                                                                                                                                               |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Sidebar, top            | Your bots. Choosing one resumes the conversation you last had open with it in this browser. **+** creates a bot.                                                           |
| Sidebar, below the bots | The selected bot's conversations, with search and filters for new replies, approval requests and archived conversations. The pen icon beside the heading starts a new one. |
| **Archive**             | The box icon on a conversation while you point at it, or in the title bar of an open one.                                                                                  |
| **New conversation**    | The pen icon in the title bar also starts an empty session with the current bot.                                                                                           |
| Notifications (bell)    | Replies, approval requests and finished scheduled jobs from every bot in one place.                                                                                        |

On a phone the bots are a strip across the top, and the workspace opens on the selected bot's conversations. Opening one fills the screen; the arrow at the top left goes back to the list.

Each session has its own link, `/sessions/<id>`. Links to a bot other than the default carry `?bot=<id>`, so a bookmarked session always opens with the right bot.

Read state is shared through the runtime: a reply you read on the desktop app is marked read here too.

### Archiving

Archiving puts a conversation away without deleting anything. It leaves the list and the notification counts, and the box icon at the end of the filters lists it. It still opens, marked **Archived** beside its title; the title bar's icon, now **Unarchive**, brings it back, as does the icon on its row. A new message also brings it back, whether you send it from an app, a channel such as Telegram sends it, or a scheduled job runs in it. Conversations cannot be deleted.

## The composer

| Control       | Use                                                                                                                                |
| ------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| Text box      | Up to 4,000 characters. **Enter** sends; **Shift+Enter** adds a line.                                                              |
| Attach files  | Up to four files per message. See [attachments](/guides/attachments/).                                                             |
| Model picker  | The model for this session. See [choosing a model](#choosing-a-model).                                                             |
| Permissions   | **Ask** (the default) or **Full access** for workspace commands and MCP tools. See [approvals](#tool-approvals).                   |
| Context donut | How full the model's context is. Hover it for the numbers, and the tokens and cost of the session so far; it turns amber past 80%. |
| Send / Stop   | Send turns into Stop while the bot is working and the draft is empty. With text in the draft, **Stop task** is under the ⋯ menu.   |

You can keep sending while the bot works. A waiting message shows as **Queued**; choose **Steer** to have the bot pick it up after its current tool step, or **Keep queued** to leave it until the current reply finishes.

Stopping withdraws queued messages, marks the interrupted reply as stopped and expires any approval request still waiting in the session. It does not undo anything a tool has already done.

## Choosing a model

The model picker lists models from the providers connected to this bot, with search, family filters and favourites. Favourites are kept in this browser.

- Choosing **before** the first message sets the new session's model.
- Choosing **later** changes only this session, and only while it is idle.
- A session keeps its model across restarts and when you change the bot's default under **Settings → Models**.

If the bot has no provider yet, the workspace prompts you to connect one; see [first run](/start/first-run/).

## Following progress

Replies stream as text with Markdown, code and Mermaid diagrams rendered. While a turn runs, tool steps appear in the reply; expand one to see its arguments and result. Each reply also reports its time, tokens and cost when the provider supplies them.

When a reply cannot finish, the conversation says why under your message, for example that the model returned an error, that no model is chosen, or that the bot used its limit of tool rounds. A model error also shows the provider's own message, such as a rate limit; anything shaped like a key is masked. The desktop app shows the same. A channel such as Telegram gets the reason without the provider's message. The **Reply failed** event in Activity records both.

For a fuller record, open **Settings → [bot] → Activity**: the bot's latest 100 events across all sessions (model calls, tools, approvals, recovery), refreshed every five seconds, with JSON export. Model reasoning is never shown. More in [observability](/operate/observability/).

## Replies

By default, bots keep replies short. A reply opens with the answer, or the one question the bot needs answered, in a sentence or two. What follows is only what you need to act on it, as a short list or table rather than paragraphs, and most replies fit in under 80 words. A reply runs longer when you ask for detail or the work is long by nature, such as code or a draft you asked for.

To change this for one bot, set its [reply style](/guides/bots/#reply-style), or say how it should reply in its [personality](/guides/bots/#edit-identity-and-personality); a personality that asks for something else wins.

## Long conversations

A session can go on as long as you like. When it grows close to the size the model can read at once, the bot summarizes its earlier messages and reads the summary instead of them from then on. Its most recent messages stay word for word.

- **When:** a summary starts in the background once the conversation fills most of the model's context window (about 154k tokens of a 200k window), and the reply waits for one only when it is nearly full (about 184k). If the provider still rejects a request as too long, the bot summarizes and tries again. A model with no known context window is summarized only after such a rejection.
- **What you see:** while a reply waits for a summary, it says **Summarizing earlier messages…**. Afterwards a line above your message reads **Earlier messages summarized**; **View summary** opens what the bot now reads. The desktop app shows the same.
- **What stays:** your transcript keeps every message, tool step and reply. Only the model's context is shortened.
- **What it costs:** the summary is one more call to the session's model, about the size of the conversation, and that turn can't read the earlier messages from the provider's prompt cache.

A summary is a record of what was said, not new instructions. Whatever it says another bot, a tool or the web wrote is still data, and it never grants permissions or approves a tool call.

## Questions from a bot

When a bot needs you to decide something before it can go on, it asks with buttons instead of writing the question out. The turn waits, and **Waiting for your answer…** shows above the question; in the conversation list the session reads **Needs your answer**.

- **Pick an answer** with one press. Answers that carry details, such as a time and a place, show as rows.
- **Answer in your own words** opens a field for anything the buttons don't cover.
- **Before something that can't be taken back**, such as deleting or sending, the action itself is the red button and the way out sits beside it.

Afterwards the question stays in the conversation with what you answered. A question waits an hour; after that, or if you stop the turn, the bot goes on without an answer and says what it still needs.

When you wrote from Telegram or Discord, the question also arrives there, with a button per answer. Only you can press them, in the chat you wrote from; once answered, the message shows your answer and loses its buttons. To answer in your own words, use the web workspace or the desktop app. An answer from any of them settles the question everywhere.

A turn started by a schedule, by another bot or in a group chat has nobody to press a button, so there the bot asks in its reply instead.

## Tool approvals

When a bot wants to run something that needs your say-so, the turn pauses and an approval card shows the exact tool and arguments.

| Choice                  | Effect                                                                                                                                                        |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Reject**              | The action does not run.                                                                                                                                      |
| **Approve once**        | Runs this exact call once.                                                                                                                                    |
| **Approve for session** | Workspace commands only. Allows the same command with the same arguments again in this session. Survives restarts; the workspace has no control to revoke it. |

Each card shows when it expires; an expired request cannot be approved. A decision made in any client or channel settles the same request everywhere.

**Permissions** apply to workspace commands and [MCP tools](/guides/tools/). **Full access** lets both run without asking in this session. It does not change sandbox limits, and an MCP server with approvals of its own still asks for them. Switching back to **Ask** stops calls that have not started yet.

:::caution
An action interrupted by a crash or restart is marked uncertain and is never repeated automatically, because it may already have taken effect. Check the result before asking again.
:::

## UI plugins

UI plugins are small, trusted additions built into the web workspace. The one included is a **token counter** beside the context donut: while you type, a rough estimate for your draft (about one token per four characters). It is hidden on a phone.

Turn plugins on or off under **Settings → UI plugins**. Plugins are not a sandbox or a marketplace, and they grant bots no extra capabilities.

## What stays in your browser

The browser keeps only conveniences; history lives in the runtime.

| Kept in browser storage                 | Scope                  |
| --------------------------------------- | ---------------------- |
| Message drafts and attached-file drafts | Per bot and session    |
| Theme, sidebar width, favourite models  | This browser, all bots |
| Last open session, local read markers   | Per bot                |
| Enabled UI plugins                      | This browser           |

Clearing site data loses unsent drafts and these preferences, never conversations.
