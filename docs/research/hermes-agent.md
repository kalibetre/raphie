# Hermes Agent and Bot Mode

## Summary

Hermes Desktop has a feature called **Bot Mode**. It gives each bot profile a pinned, long-lived **Bot Chat** and exposes routines beside it. Its **messaging gateway** is a separate entry point with its own routing and session commands. Both can keep a chat going across restarts. Hermes limits active context through in-place compaction and retrieves older messages from SQLite when needed. Work that outlives a turn can use a background session, cron, or a durable Kanban card. The closest fit for Raphie is a stable chat with a compact working context and independently persisted work state. [Bot Mode](https://hermes-agent.nousresearch.com/docs/user-guide/bot-mode), [Messaging Gateway](https://hermes-agent.nousresearch.com/docs/user-guide/messaging#session-management), [Compaction](https://hermes-agent.nousresearch.com/docs/developer-guide/context-compression-and-caching#in-place-compaction-single-stable-session-id), [Kanban](https://hermes-agent.nousresearch.com/docs/user-guide/features/kanban)

## 1. What it is and how mature it is

Nous Research builds Hermes Agent as a self-hostable, provider-flexible assistant runtime for personal assistants, coding, research, automation, and teams of specialist agents. It has terminal, Desktop, web, and messaging interfaces. Profiles keep separate configuration, state, and memory so a user can run several specialists on one installation. The upstream standalone Bot Mode plugin is archived because the plugin now ships with Desktop and is enabled by default. [Project README](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/README.md), [Profiles](https://hermes-agent.nousresearch.com/docs/user-guide/profiles), [Original Bot Mode repository](https://github.com/NousResearch/Hermes-Bot-Mode#readme)

The latest release shown was **v0.23.4**, dated November 23 in its notes, which report 229 merged PRs since v0.23.3. That establishes active development and substantial public interest. ## 2. Chat identity, routing, and resets

**Desktop Bot Mode.** A bot is an existing Hermes profile surfaced in the Desktop roster. The roster opens the profile's pinned canonical session, titled `Bot Chat`. The plugin resolves it by profile and exact title, and adopts an existing row if another client wins the creation race. Ordinary sessions still exist and can be opened through the regular session UI or the bot's recent-session action. The Bot Chat composer translates `/new` and `/reset` into `/compact`. Explicitly archiving the Bot Chat retires it and the next open creates a new canonical chat, with the retired history still in the database. Automatic idle archiving skips Bot Chat. [Bot Mode, Bots pane](https://hermes-agent.nousresearch.com/docs/user-guide/bot-mode#the-bots-pane), [Canonical lookup and creation](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/apps/desktop/src/plugins/hermes-bots/canonical-chat.ts#L526-L589), [Desktop composer middleware](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/apps/desktop/src/plugins/hermes-bots/plugin.tsx#L749-L800)

**Messaging gateway.** Inbound messages resolve to a deterministic route key, which points to the active durable session. The key includes the profile namespace, platform, chat type, and available chat/thread IDs, plus Slack workspace scope where present. A DM normally uses its chat ID, falling back to sender ID if necessary. For group and channel messages outside a thread, the default adds the participant ID when available. A thread has its own route and is shared by its participants by default in the release code. Enable `thread_sessions_per_user` alongside `group_sessions_per_user` to partition it by sender. The published configuration guide's statement that the group setting alone partitions threads disagrees with the tagged routing function and defaults. Slack also defaults to treating top-level DMs as separate sessions unless configured as a rolling DM. The source key explains why joining two platforms to one profile does not give the owner one shared DM history across them. [Route construction](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/gateway/session.py#L722-L768), [Gateway defaults](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/gateway/config.py#L611-L639), [Configuration guide](https://hermes-agent.nousresearch.com/docs/user-guide/configuration), [Slack DM behavior](https://hermes-agent.nousresearch.com/docs/user-guide/features/cron#flat-in-channel-continuation-slack)

**Gateway rollover versus compaction.** There is no core daily or idle reset. The optional reset-policy plugin restores time-based rollover. In ordinary messaging chats, `/new` and `/reset` replace the active session for the same route and end the old row. Scoped `/sessions` and `/resume` expose prior sessions. Cache eviction can release the agent instance while leaving the durable session intact. Under the default `compression.in_place: true`, compression keeps the session ID and marks old transcript rows compacted/inactive. The optional legacy path creates parent-linked continuation sessions. The general Sessions guide describes rotation without that qualification, so use the compaction guide and release defaults for current behavior. [Messaging continuity](https://hermes-agent.nousresearch.com/docs/user-guide/messaging#session-continuity), [Released reset policy](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/gateway/session_lifecycle.py#L159-L161), [Reset implementation](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/gateway/session.py#L1207-L1237), [Release defaults](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/hermes_cli/config_defaults.py#L662-L679), [In-place compaction](https://hermes-agent.nousresearch.com/docs/developer-guide/context-compression-and-caching#in-place-compaction-single-stable-session-id), [Sessions guide](https://hermes-agent.nousresearch.com/docs/user-guide/sessions#auto-lineage-on-compression)

## 3. Context, retrieval, and cost

**When it compresses.** The built-in agent compressor starts from a configured 50% trigger. In the release, windows below 512K raise that percentage to at least 75%, explicit output reservation reduces the input budget, an absolute token cap can lower the trigger, and route/model overrides can change it. The gateway separately runs a pre-turn safety check at 85% of the model window or a configurable hard message count (5,000 by default, with at least four history rows and compression enabled). It prefers reported prompt usage, then a persisted usage anchor, then a rough estimate. The agent can react during the tool loop, including to provider overflow. A fresh over-threshold estimate can wait for one provider measurement before driving normal in-loop compression. Manual `/compress` can bypass a failure cooldown. [Agent threshold calculation](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/agent/context_compressor.py#L2603-L2668), [Gateway checks](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/gateway/run_turn_hygiene.py#L68-L104), [Gateway token selection](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/gateway/run_turn_hygiene.py#L156-L195), [Provider anchors and overflow](https://hermes-agent.nousresearch.com/docs/developer-guide/context-compression-and-caching#token-accounting-provider-anchors-and-explicit-heuristic-fallbacks), [Manual compression](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/agent/context_compressor.py#L5021-L5038)

**What survives verbatim.** It plans the window on a pruned copy, then builds the summarizer input from original middle rows subject to serialization limits. It protects a recent tail measured in tokens and aligns cuts around tool call/result boundaries. Default lean mode targets about 2.5% of the main model window, normally 10K–25K tokens, with extra caps for small budgets. The default recent-message setting is 20 and at least one genuine user message survives. The count gives way to the token budget, with exceptions for protected anchors and tool groups. Recent unanswered tool work generally keeps its results, with an oversized-round exception. Stale results in the tail can be shortened or replaced with file references, so a retained tail can contain pruned results. The first few messages lose their special protection after the first compaction, except for a delegated child's brief. [Window planner](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/agent/context_compressor_window.py#L54-L145), [Tail limits](https://hermes-agent.nousresearch.com/docs/developer-guide/context-compression-and-caching#auxiliary-feasibility-and-tail-retention), [Pruning and window rules](https://hermes-agent.nousresearch.com/docs/developer-guide/context-compression-and-caching#compression-algorithm), [Defaults](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/hermes_cli/config_defaults.py#L577-L602)

**What the summary says.** The auxiliary model gets the prior summary plus newly compacted turns on subsequent passes. Its release template asks for the last unfinished user request, goals and constraints, concrete actions and outcomes, active state, blockers, decisions, errors and fixes, resolved questions, relevant files, and exact details worth keeping. It asks for source attribution, distinguishes conjecture, and redacts secrets. Lean mode can add a bounded index, selected user wording, and recovery pointers. Removed skill instructions get a marker directing the model to reload the skill. When summarization fails, the release can preserve the original live history or build a deterministic fallback, depending on the failure path. Window changes are committed after a summary exists. [Summary prompt](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/agent/context_compressor.py#L3670-L3808), [Lean additions](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/agent/context_compressor.py#L3444-L3456), [Failure and commit path](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/agent/context_compressor.py#L5105-L5135)

**Retrieval.** `session_search` queries SQLite FTS5 and returns actual stored messages without an auxiliary model call. It supports keyword discovery with date/role filters, session browse and bounded reads, and scrolling around a specific message ID. Discovery deduplicates old rotation lineages, and knows to return hits from an archived segment of the current in-place session. This supports recovering a decision verbatim after it leaves the live context. The separate `/sessions search` command searches titles and IDs. [FTS discovery and live-context filtering](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/tools/session_search_tool.py#L449-L539), [Browse, read, and scroll](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/tools/session_search_tool.py#L595-L759), [Messaging session picker](https://hermes-agent.nousresearch.com/docs/user-guide/messaging#finding-past-sessions-sessions)

**Cost.** Hermes makes provider-specific prompt-cache plans around stable prefixes and recent message endpoints. On Anthropic-compatible routes the release can place markers at the stable and full system-prompt edges plus two recent messages, or use one system edge and three recent messages when there is no stable split. Direct native Anthropic can instead reserve a marker for the tools schema and use completed transaction boundaries. Auto TTL selects 1 hour for human-paced chat and 5 minutes for machine-paced runs, with route limits. Changing an early prompt segment, model, or account can lose cache hits. Additional controls include an independently routed summary model, an optional absolute compaction trigger, early pruning of oversized old tool results, and opt-in preparation of the next summary ahead of compaction. The savings depend on provider pricing, cadence, and how often the prefix changes. [Cache plan source](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/agent/prompt_caching.py#L469-L538), [TTL source](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/agent/prompt_caching.py#L152-L186), [Caching and compaction guide](https://hermes-agent.nousresearch.com/docs/developer-guide/context-compression-and-caching)

## 5. Memory and skills

Hermes has two default profile-local memory files. `MEMORY.md` holds agent notes such as durable environment facts and conventions, with a default 2,200-character limit. `USER.md` holds the user's preferences and expectations, with a 1,375-character limit. Both enter the system prompt as a snapshot to preserve the cache prefix. Allowed writes update the live store immediately. The memory guide describes refresh at session start. In the release, live compaction also rebuilds the system prompt and reloads disk memory. A detached gateway hygiene pass can preserve the seeded prompt instead. A saved correction may therefore take time to reach the prompt of a running chat. When a write exceeds the limit, the tool rejects it and the model can consolidate entries. [Persistent memory](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory), [Prompt refresh on compaction](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/agent/conversation_compression.py#L3024-L3079), [Reload from disk](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/agent/system_prompt.py#L850-L866), [Memory configuration](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/hermes_cli/config_defaults.py#L1261-L1275)

Foreground writes use the `memory` tool. Automatic learning can also run a post-turn review fork that decides whether to make tool calls for durable facts or reusable procedures. Memory review is eligible every 10 turns by default when the memory tool and store are available. Skill creation has a separate interval, also initialized to 10. Settings can disable automatic review or route it to a different auxiliary model. An optional approval setting stages tool-mediated writes for review, and the background fork stages destructive edits even when the general gate is off. Treat this as model-selected recording, with review and budget controls. [Memory turn counter](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/agent/turn_context.py#L818-L827), [Nudge initialization](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/agent/agent_init.py#L1141-L1226), [Review controls](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory#background-review-notifications-displaymemory_notifications), [Write gate](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/tools/memory_tool.py#L84-L142), [Destructive review operations](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/tools/memory_tool.py#L173-L240)

Skills provide procedural memory. Hermes advertises a compact skill index and uses `skill_view` to fetch a skill's instructions on demand. `skill_manage` can create and edit skills. `SOUL.md` and project context files are separate prompt inputs for identity and working instructions. Historical recall uses `session_search` independently of both built-in files. Optional memory provider plugins can contribute tool schemas and query-based prefetch, sync completed turns, and participate at session and compaction boundaries. ## 6. Runtime and storage

```text
Desktop Bot Mode / CLI / TUI / API     Telegram / Discord / Slack adapters
                |                                      |
                +---------- gateway session ownership / routing
                                         |
              cron and Kanban workers --> AIAgent turn loop --> model provider
                                         |          |
                                prompt assembly     tool registry and adapters
                                         |
                           SQLite session state and FTS5
                            profile files / cron state
```

The agent runtime is Python. Desktop Bot Mode is a TypeScript plugin over the profile and session APIs. The gateway owns canonical session writes, routes adapter input, and serves local clients over WebSocket. `AIAgent` assembles the prompt, prepares and checks requests, calls the configured provider, then either runs a tool round or finishes the response. The tool registry discovers and filters schemas by toolset and dispatches calls through hooks and middleware. Skills are indexed by the prompt builder and loaded by tools, and the built-in compressor can be replaced with a context-engine plugin. [Python package](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/pyproject.toml#L5-L18), [Desktop plugin](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/apps/desktop/src/plugins/hermes-bots/plugin.tsx#L25-L90), [Session ownership](https://hermes-agent.nousresearch.com/docs/developer-guide/session-storage), [Turn loop](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/agent/conversation_loop.py#L1724-L1774), [Tool registry](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/model_tools.py#L1-L24), [Context engine](https://hermes-agent.nousresearch.com/docs/developer-guide/context-compression-and-caching#pluggable-context-engine)

In the tagged scheduler, agent cron runs can load profile memory while skipping automatic review forks. ## Lessons for Raphie

1. **Build on the existing stable chat and compacted model view.** Raphie already has a 64K working threshold for large windows, background summaries, a blocking threshold that reserves output room, and provider-overflow recovery. Keep those defaults pending measurements. The additions worth trying are a floor of genuine owner messages in the recent tail, preservation of pending tool rounds, and quote/message IDs for recoverable details. Keep the summary focused on commitments, precise decisions, unresolved questions, and provenance. Hermes's lean tail and cost controls give options to measure against Raphie's current token policy. [Raphie compaction policy](../../packages/runtime/src/domains/conversations/domain/compaction.ts), [Raphie execution design](../../apps/docs/src/content/docs/architecture/execution.mdx), [Hermes tail limits](https://hermes-agent.nousresearch.com/docs/developer-guide/context-compression-and-caching#auxiliary-feasibility-and-tail-retention)
2. **Give the model a bounded transcript lookup with quoteable results.** Search a bot's chat by text, date, or speaker and return exact excerpts with message IDs and nearby context. This lets an owner ask for an old decision after compaction without making every turn replay it. Use the existing chat and channel binding to scope access, and label rewound material so it can be read as history without reviving superseded instructions. Hermes demonstrates FTS5, followed by a bounded read around a hit. [Raphie chat, quote and rewind](../../CONTEXT.md), [Hermes discovery and scroll](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/tools/session_search_tool.py#L449-L539)
3. **Project current work items into every turn from durable state.** Give the model each open item's ID, title, status, and next dependency or due time, then fetch full notes/results on demand. Use the existing Work page for management and a quote or linked item in chat to disambiguate follow-ups. Hermes's todos show why active task state needs to survive compaction, while its Kanban board shows how stable IDs and state transitions support restart-safe work. Raphie can get those benefits from its own work item model without adding a session picker or another board. [Raphie work items](../../CONTEXT.md), [Hermes todo injection](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/tools/todo_tool.py#L89-L131), [Hermes Kanban](https://hermes-agent.nousresearch.com/docs/user-guide/features/kanban)
4. **Bring important completion and blocked events back to the originating chat.** Keep a work item's background session available for follow-ups while the item is open. Persist completion, chat delivery, and any decision to wake the bot independently. Give a result or blocker a quote back to the owner's request when one exists. Ordinary notifications can be presented without a model turn, and a wake can be reserved for work that needs interpretation. Avoid making every scheduled result a new thread or sending a handoff into the receiving bot's owner chat. Hermes's Kanban and cron delivery modes show the cost and follow-up consequences of those choices. [Raphie work items, handoffs, quotes and delivery](../../CONTEXT.md), [Hermes Kanban delivery modes](https://hermes-agent.nousresearch.com/docs/user-guide/features/kanban#delivery-modes), [Hermes cron Bot Chat delivery](https://hermes-agent.nousresearch.com/docs/user-guide/features/cron#bot-chat-delivery-bot-chat)
5. **Keep live owner corrections available without rewriting the stable prompt on every turn.** Keep the installed instructions and slow-changing context early in the prompt. Retrieve current, sourced memory evidence in a bounded later segment, and keep changes to the owner profile governed by Raphie's existing self-update settings. Refreshing a memory snapshot at compaction protects cache locality and leaves a gap after a correction is saved. Read updated evidence on the next turn when freshness matters.
