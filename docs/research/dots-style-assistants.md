# Dots-style assistants

## Summary

OpenAI launched **dots** on September 29, 2026. A dot has a main ChatGPT chat, can keep working while the owner talks to it, and can surface results, decisions, and scheduled runs there. Slack conversations and delegated Work or Codex tasks can have their own visible histories. [Launch](https://openai.com/index/introducing-dots/) · [Tasks and memory](https://learn.chatgpt.com/docs/dots/tasks-and-memory) · [Help Center](https://help.openai.com/en/articles/20001530-getting-started-with-your-dot)

There are several real repositories with similar names. **CopilotKit/OpenDots** is the largest exact-name match and now lives as an OpenBot skin. **diggerhq/opendots** is the closest match for one main chat coordinating durable work. **Suparagent**, formerly Anil-matcha/open-dots, has the clearest inspectable compaction and recall policy. Composio's Open Dot demonstrates simple context limits. Shafreeck's opendots demonstrates bounded context through Morphz and exactly addressed background work. [CopilotKit/OpenDots](https://github.com/CopilotKit/OpenDots) · [Digger OpenDots](https://github.com/diggerhq/opendots) · [Suparagent repository redirect](https://github.com/Anil-matcha/open-dots) · [Composio Open Dot](https://github.com/composio-community/open-dot) · [Shafreeck opendots](https://github.com/shafreeck/opendots)

Reviewed on November 26, 2026. GitHub stars and default-branch dates are snapshots, and implementation links are pinned. This is a source review. The report attributes live checks to their authors where applicable.

## OpenAI dots

- **Product and maturity.** Hosted ChatGPT feature for ongoing personal and work responsibilities. It shipped with GPT-6 Astra, and the current guide also names GPT-6.1 Terra and says a dot can use different models for different parts of work. The Help Center lists eligible Pro, Business, and Enterprise-family accounts and a gradual Plus rollout. There is no public dots implementation or project license in the sources reviewed. [Launch](https://openai.com/index/introducing-dots/) · [Product guide](https://learn.chatgpt.com/docs/dots) · [Availability](https://help.openai.com/en/articles/20001530-getting-started-with-your-dot)
- **Chat and ongoing work.** The same main ChatGPT chat is accessible across supported ChatGPT clients. Slack has its own visible history with continuity through relevant context and notes. The owner can redirect ongoing work in chat, while the desktop profile's Activity view exposes progress, files, results, and requests for input. Independent cloud tasks have their own visible conversations, and local Codex tasks appear on the connected computer. New tasks receive a scoped brief from the dot. [Clients and channels](https://learn.chatgpt.com/docs/dots#your-dot-wherever-you-are) · [Assigned work](https://learn.chatgpt.com/docs/dots/tasks-and-memory#assigned-work)
- **Context and cost.** A turn sees selected messages, instructions, source material, delegated results, and tool output. The dot can search previous ChatGPT chats for relevant material. Calls may see a different selection from background work. OpenAI does not publish dots-specific window thresholds, rolling-tail size, summary schema, retrieval ranking, or cache policy in these sources. The launch explains plan usage and separate accounting for delegated Work or Codex tasks. OpenAI independently documents Codex threshold-triggered compaction and API caching behavior, but the dots system card distinguishes the two harnesses. [Context and memory](https://learn.chatgpt.com/docs/dots/tasks-and-memory#context-and-memory) · [Launch usage](https://openai.com/index/introducing-dots/#get-started-with-dots) · [Codex loop](https://openai.com/index/unrolling-the-codex-agent-loop/) · [Dots system card](https://deploymentsafety.openai.com/gpt-6-astra/sec%3Aappendix-202717)
- **Work lifecycle and architecture.** ChatGPT and messaging channels reach the hosted dot, which has its own cloud computer and browser, permissioned plugins, and optional connected computers. Background agents can run in parallel. The dot can pause and wake itself to follow through, use fixed reminders or schedules, or monitor supported service events. Scheduled runs and proactive updates can land in chat. Pausing the main run, stopping delegated work, and canceling schedules have separate controls. The system card documents a time budget guiding how long a dot works. The storage engine and task state schema are undisclosed. [Product guide](https://learn.chatgpt.com/docs/dots#how-your-dot-works) · [Recurring work and events](https://learn.chatgpt.com/docs/dots/tasks-and-memory#recurring-tasks) · [Help Center](https://help.openai.com/en/articles/20001530-getting-started-with-your-dot) · [System card](https://deploymentsafety.openai.com/gpt-6-astra/sec%3Aappendix-202717)
- **Memory.** ChatGPT can share relevant memory and recent chat context with the dot after setup. The dot maintains its own notes on preferences, decisions, and ongoing responsibilities. Read-only proactive research can add private notes using permitted sources without a new owner message. The write mechanism and selection algorithm are undisclosed. Individual dot memories cannot currently be inspected, edited, or removed directly. Deleting the dot starts deletion of its context, with separate lifecycles for ChatGPT memory, delegated conversations, and files. [Tasks and memory](https://learn.chatgpt.com/docs/dots/tasks-and-memory#persistent-memory) · [Privacy and memory FAQ](https://help.openai.com/en/articles/20001529-dots-privacy-security-and-safety-faqs)
- **For Raphie.** Use chat for steering and meaningful updates, with the Work page for inspection. Keep separate controls for an active turn, a work item's background session, and a schedule. Exposing delegated chats and making memory corrections depend on reset would conflict with Raphie's model. [OpenAI controls](https://learn.chatgpt.com/docs/dots/controls#stop-work) · [Raphie context](../../CONTEXT.md)

## CopilotKit OpenDots

- **Product and maturity.** MIT single-owner web and mobile template for specialist coworkers, text, voice, Slack, and live computers. GitHub reported **6,776 stars**. The November 25 default-branch commit includes the maintainer's notice ending standalone maintenance and pointing to OpenBot. [Repository](https://github.com/CopilotKit/OpenDots) · [Migration notice](https://github.com/CopilotKit/OpenDots/blob/f59b1d32c91ed70eaf8435caace4732ed438acf1/README.md#L13-L46)
- **Chat model and work.** The UI explicitly offers **New conversation** and lists existing ones. Specialist Dots and Space pages can have different chats. Voice runs realtime speech alongside a compute agent using the conversation context, and Slack continues in its own thread. The server runs recurring tasks in their originating chat, labels scheduled messages, and exposes scheduled work, activity, pause, and reviewed retry. An interrupted lease leaves the run marked interrupted. The standalone README lists automatic delegation and richer goal/event triggers as future work. [Thread list](https://github.com/CopilotKit/OpenDots/blob/f59b1d32c91ed70eaf8435caace4732ed438acf1/src/client/ThreadList.tsx#L17-L62) · [Voice and Slack](https://github.com/CopilotKit/OpenDots/blob/f59b1d32c91ed70eaf8435caace4732ed438acf1/README.md#L128-L158) · [Task runner and verified scope](https://github.com/CopilotKit/OpenDots/blob/f59b1d32c91ed70eaf8435caace4732ed438acf1/README.md#L227-L251)
- **Context, memory, and architecture.** React/CopilotKit and TanStack AI handle streamed requests. CopilotKit Intelligence persists messages, tool calls, and run events. SQLite holds app state, page and chat bindings, scheduled jobs, and manually managed memory. Both owner and Dot switches gate use of the local memory list. The agent reads all enabled entries in that list, with no per-message retrieval in this path. Automatic Learning routes conversation evidence to Intelligence and delivers published skills. This is a separate write path from the editable preference list. The checked app path gives no token-triggered summary, rolling-turn budget, or prompt-cache settings for chat history. [Data boundaries](https://github.com/CopilotKit/OpenDots/blob/f59b1d32c91ed70eaf8435caace4732ed438acf1/README.md#L164-L188) · [SQLite schema](https://github.com/CopilotKit/OpenDots/blob/f59b1d32c91ed70eaf8435caace4732ed438acf1/src/server/store.ts#L26-L36) · [Memory injection](https://github.com/CopilotKit/OpenDots/blob/f59b1d32c91ed70eaf8435caace4732ed438acf1/src/server/dot-agent.ts#L321-L337) · [Learning and validation](https://github.com/CopilotKit/OpenDots/blob/f59b1d32c91ed70eaf8435caace4732ed438acf1/README.md#L239-L251)

Keep bulky job activity in the work item's session and surface a short result in chat. [Scheduled run behavior](https://github.com/CopilotKit/OpenDots/blob/f59b1d32c91ed70eaf8435caace4732ed438acf1/README.md#L235-L251) · [Raphie context](../../CONTEXT.md)

## CopilotKit OpenBot

- **Product and maturity.** Maintained successor, with personal Desktop and team deployment options. GitHub reported **13,612 stars** and a November 26 default-branch commit. The template is MIT. The core server, computer, and supervisor ship as published images, and CopilotKit Intelligence is separately licensed. The skin changes the presentation over the same backend. [Repository](https://github.com/CopilotKit/OpenBot) · [Licensing](https://github.com/CopilotKit/OpenBot/blob/5ff641de36cb5e459ed01637106912b4b5ba416d/README.md#L106-L116) · [Architecture](https://github.com/CopilotKit/OpenBot/blob/5ff641de36cb5e459ed01637106912b4b5ba416d/docs/architecture.md#L12-L29) · [Skin migration](https://github.com/CopilotKit/OpenDots/blob/f59b1d32c91ed70eaf8435caace4732ed438acf1/README.md#L20-L43)
- **Chat and work.** Multiple persistent conversations and channels, with separate Bot pages for Routines and Activity. One Routines list combines repeatable instructions, goals, and proactive check-ins. The stores distinguish the three. A goal can start on request, by a schedule that points to it, or on an event. It reports to the initiating or designated conversation. Check-ins are advisory. Routines use a 15-minute floor, a 20-enabled-per-person cap, and suspend after ten consecutive failures. The server skips stale occurrences and uses a durable queue key for each due occurrence. [Main surfaces](https://github.com/CopilotKit/OpenBot/blob/5ff641de36cb5e459ed01637106912b4b5ba416d/README.md#L385-L402) · [Work model and tools](https://github.com/CopilotKit/OpenBot/blob/5ff641de36cb5e459ed01637106912b4b5ba416d/docs/routines.md#L8-L89) · [Limits and dispatch](https://github.com/CopilotKit/OpenBot/blob/5ff641de36cb5e459ed01637106912b4b5ba416d/docs/routines.md#L107-L161)
- **Context, memory, and cost.** The changelog reports longer tool runs for built-in Bots. I could not verify the server's exact threshold, summary contents, rolling tail, or provider cache policy from the public template and docs. The pinned architecture distinguishes Desktop personal edition, where Memory is unavailable, from team memory. Team memory tracks owner-confirmed or authored facts, review state, and provenance. Entitled deployments rank recall via Intelligence with OpenBot applying visibility filters, with local-table fallback. Intelligence documents hybrid recall, and OpenBot documents keyword-only mode without the embeddings service. The newer changelog says automatic per-app memory imports were switched off and unreviewed imports from those sources removed. Learning from completed work produces reviewable skills through a separate service. [Changelog](https://open.bot/changelog) · [Memory architecture](https://github.com/CopilotKit/OpenBot/blob/5ff641de36cb5e459ed01637106912b4b5ba416d/docs/architecture.md#L370-L395) · [Intelligence recall](https://docs.copilotkit.ai/google-antigravity/intelligence/memories#how-recall-works) · [Keyword fallback](https://open.bot/resources/enterprise-agent-guide) · [Learning](https://github.com/CopilotKit/OpenBot/blob/5ff641de36cb5e459ed01637106912b4b5ba416d/docs/automatic-learning.md#L24-L34)
- **Architecture and Raphie takeaway.** React and channel clients use a Hono server. AG-UI connects built-in or remote agents, MCP supplies tools, PostgreSQL stores configuration, audit and queued work, and Intelligence stores durable threads. The computer gateway applies policy and records actions. Borrow the Work-page projection and explicit stop conditions for repeated work. Raphie's in-process scheduler and SQLite already cover the deployment shape it needs. [OpenBot architecture](https://github.com/CopilotKit/OpenBot/blob/5ff641de36cb5e459ed01637106912b4b5ba416d/docs/architecture.md#L1-L29) · [Work rules](https://github.com/CopilotKit/OpenBot/blob/5ff641de36cb5e459ed01637106912b4b5ba416d/docs/routines.md#L69-L92) · [Raphie system overview](../../apps/docs/src/content/docs/architecture/overview.mdx)

## Digger OpenDots

- **Product and maturity.** MIT single-owner, model-agnostic preview. GitHub reported **29 stars** and a September 29 default-branch commit. The TanStack Start app owns authentication, the session index, and delegation. OpenComputer Serverless Agents runs a TypeScript coordinator and topic worker, stores durable transcripts and notes, and provisions a computer for the worker on demand. Closing the browser leaves managed work running. Local setup still needs a reachable app for callback delegation and fallback delivery. [Repository](https://github.com/diggerhq/opendots) · [Architecture and maturity](https://github.com/diggerhq/opendots/blob/fbdf673f2648507cf4710ed00d480ba787f4e3a8/README.md#L110-L155) · [Outcome delivery](https://github.com/diggerhq/opendots/blob/fbdf673f2648507cf4710ed00d480ba787f4e3a8/docs/development.md#L48-L65)
- **One main chat with reusable work.** The coordinator answers short requests directly. For longer work it reads topic summaries and inspects likely matches before calling `start_topic` with an existing ID or a title. The app binds one ongoing worker session to each topic and derives an idempotency key from the tool invocation. The owner can open the topic's conversation, edit notes, follow up, or stop the worker. Terminal worker outcomes become typed turns in the coordinator by event subscription, with an app-side fallback. They include worker session and turn identifiers and are presented as evidence rather than owner input. The fallback's Cloudflare cron dispatches outcomes. I found no owner-facing recurring job or reminder feature in this snapshot. [Coordinator](https://github.com/diggerhq/opendots/blob/fbdf673f2648507cf4710ed00d480ba787f4e3a8/opencomputer/agents/coordinator/agent.ts#L9-L29) · [Invocation key](https://github.com/diggerhq/opendots/blob/fbdf673f2648507cf4710ed00d480ba787f4e3a8/opencomputer/agents/coordinator/tools/start-topic.ts#L32-L49) · [Topic service](https://github.com/diggerhq/opendots/blob/fbdf673f2648507cf4710ed00d480ba787f4e3a8/src/lib/topics/service.ts#L72-L164) · [Return path](https://github.com/diggerhq/opendots/blob/fbdf673f2648507cf4710ed00d480ba787f4e3a8/docs/development.md#L48-L70)
- **Context and cost.** A focused brief and separate context keep the worker's tool loop outside the coordinator's replay. Replacement sessions start with the saved documents, while prior transcripts remain available for inspection. OpenComputer's memory docs say documents survive compaction. Neither the app nor the platform docs examined establish the managed runtime's compaction threshold, summary contents, rolling window, or prompt-cache behavior. The coordinator's injected topic overview cost as topics accumulate was unmeasured. [Coordinator prompt](https://github.com/diggerhq/opendots/blob/fbdf673f2648507cf4710ed00d480ba787f4e3a8/opencomputer/agents/coordinator/agent.ts#L9-L29) · [Session replacement](https://github.com/diggerhq/opendots/blob/fbdf673f2648507cf4710ed00d480ba787f4e3a8/docs/development.md#L35-L46) · [Platform sessions](https://docs.opencomputer.dev/agents/sessions) · [Platform memory](https://docs.opencomputer.dev/agents/memory#save-and-reuse-notes)
- **Memory.** The coordinator reads and writes the owner profile and browses the topic collection by summary or explicit `memory_read`. A worker reads the profile and reads or writes its own topic. Notes hold the brief, constraints, decisions, sources, verified commands or revisions, and unfinished work. The worker is prompted to save at meaningful progress points. The model explicitly calls `memory_save`, which replaces the document with a revision check. Owners can edit the same notes. OpenComputer rereads bound documents at each model step and does no automatic extraction from chat history. [Memory resource definitions](https://github.com/diggerhq/opendots/blob/fbdf673f2648507cf4710ed00d480ba787f4e3a8/scripts/templates/memory.ts#L1-L25) · [Worker prompt](https://github.com/diggerhq/opendots/blob/fbdf673f2648507cf4710ed00d480ba787f4e3a8/opencomputer/agents/topic-worker/agent.ts#L4-L34) · [OpenComputer write and read semantics](https://docs.opencomputer.dev/agents/memory#save-and-reuse-notes)
- **For Raphie.** Reuse the stable work identity, durable outcome routing, and owner-correctable notes. Keep the worker's session implicit and use the existing Work page for details. Keep the local index transactional with SQLite. Digger documents eventual consistency and lost concurrent writes for its optional Cloudflare KV index. [App state and storage](https://github.com/diggerhq/opendots/blob/fbdf673f2648507cf4710ed00d480ba787f4e3a8/docs/configuration.md#L54-L76) · [Raphie context](../../CONTEXT.md)

## Suparagent, formerly Anil-matcha/open-dots

- **Product and maturity.** The former URL redirects to Suparagent. It is an Apache-2.0 desktop and self-hosted workspace for personal assistants and coordinated agent teams, with a separately operated hosted version. GitHub reported **7,172 stars** and a November 26 default-branch commit. Next.js and desktop clients reach a FastAPI backend using SQLite or PostgreSQL. The backend owns conversations, turns, approvals, agent data and routines, and uses engine adapters for Claude, Codex, ACP and API-backed models. [Redirect](https://github.com/Anil-matcha/open-dots) · [Repository](https://github.com/Anil-matcha/suparagent) · [Architecture](https://github.com/Anil-matcha/suparagent/blob/c0cd2b155859b3c421c9592f017376df7d71f696/docs/ARCHITECTURE.md#L1-L80)
- **Chat and ongoing work.** An agent can have several direct conversations, participate in rooms, and run delegated work or routines in their own conversations. A lead can delegate to up to four teammates and end its current turn immediately. A durable inbox collects results and resumes the lead once in the same conversation with the outcomes when awaited jobs settle or a teammate asks a question. Users can inspect jobs and answer teammate questions in that teammate's own conversation. [Teams and delegation](https://github.com/Anil-matcha/suparagent/blob/c0cd2b155859b3c421c9592f017376df7d71f696/docs/TEAMS.md#L12-L14) · [Lead and job lifecycle](https://github.com/Anil-matcha/suparagent/blob/c0cd2b155859b3c421c9592f017376df7d71f696/docs/TEAMS.md#L58-L85)
- **Schedules and reporting.** IANA-timezone cron, weekdays, interval, one-shot, or manual/webhook runs. The scheduler admits at most the latest in-window missed occurrence, skips overlap while an earlier run is active, and creates a new conversation linked to each run. An interrupted active run is recorded without automatic replay. Outcomes and needs-input states appear in an in-app feed, with optional Telegram delivery. Quiet reporting requires an explicit no-change outcome and complete successful read receipts. [Schedule policy](https://github.com/Anil-matcha/suparagent/blob/c0cd2b155859b3c421c9592f017376df7d71f696/docs/ROUTINES.md#L12-L74) · [Restart recovery](https://github.com/Anil-matcha/suparagent/blob/c0cd2b155859b3c421c9592f017376df7d71f696/docs/ROUTINES.md#L122-L132) · [Notifications](https://github.com/Anil-matcha/suparagent/blob/c0cd2b155859b3c421c9592f017376df7d71f696/docs/ROUTINES.md#L188-L202) · [Quiet results](https://github.com/Anil-matcha/suparagent/blob/c0cd2b155859b3c421c9592f017376df7d71f696/docs/ROUTINES.md#L323-L333)
- **Context compaction.** Claude and Codex keep their own sessions and CLI compaction. For a history-replaying OpenAI-compatible engine or an ACP engine that cannot reload a session, the app estimates input before replay. The trigger is 24,000 estimated tokens by default, or 80% of an explicitly configured OpenAI-compatible window. It keeps the current message plus up to four complete prior exchanges, dropping to one when needed to target 70% of its budget. Its fallback is a redacted ordered set of recent excerpts with the earlier summary and counts for omitted content, capped at 6,000 characters. The optional model pass is on by default where supported, has a 20-second deadline, and preserves latest goals, corrections, constraints, decisions, exact details, completed and open work, and attribution. Up to 2,600 characters of model summary are kept with the newest excerpts. A durable `context.compacted` event records the fold boundary, method, and estimated sizes. Future requests reuse it until the next fold, while the UI can show both the summary and the intact transcript. An oversized live exchange can still exceed the engine's limit. [Detailed policy](https://github.com/Anil-matcha/suparagent/blob/c0cd2b155859b3c421c9592f017376df7d71f696/docs/MEMORY.md#L162-L225) · [Fold implementation](https://github.com/Anil-matcha/suparagent/blob/c0cd2b155859b3c421c9592f017376df7d71f696/backend/app/services/context_compaction.py#L221-L273) · [Summary prompt](https://github.com/Anil-matcha/suparagent/blob/c0cd2b155859b3c421c9592f017376df7d71f696/backend/app/services/context_compaction.py#L276-L306)
- **Memory and cost.** Markdown tiers include an always-loaded `MEMORY.md` prefix bounded by 200 lines and 24 KB, a bounded topic index, topic files read in part, archives, daily logs, and an external change journal. Users edit and approve deterministic proposals drawn from durable statements. Automatic upkeep batches eligible private turns after two minutes of quiet or six turns, then saves small redacted and reversible facts directly to core or topic notes. An optional helper handles eligible summary and memory calls. Local lexical recall adds up to four notes and four passages from other conversations within 6,000 characters, with provenance visible in the UI. The current conversation is excluded from automatic recall, so a one-chat product must adapt that policy to search older compacted messages. Explicit search/read tools are available on supported engines. Recall goes next to the new message to preserve the more stable prompt prefix. An off-by-default cache warmer makes real lightweight Claude/Codex turns, with defaults of three chats, two idle hours, and four minutes between calls. [Memory tiers](https://github.com/Anil-matcha/suparagent/blob/c0cd2b155859b3c421c9592f017376df7d71f696/docs/MEMORY.md#L8-L61) · [Recall](https://github.com/Anil-matcha/suparagent/blob/c0cd2b155859b3c421c9592f017376df7d71f696/docs/MEMORY.md#L114-L160) · [Proposals and upkeep](https://github.com/Anil-matcha/suparagent/blob/c0cd2b155859b3c421c9592f017376df7d71f696/docs/MEMORY.md#L227-L303) · [Search tools](https://github.com/Anil-matcha/suparagent/blob/c0cd2b155859b3c421c9592f017376df7d71f696/docs/MEMORY.md#L334-L363) · [Helper](https://github.com/Anil-matcha/suparagent/blob/c0cd2b155859b3c421c9592f017376df7d71f696/docs/MEMORY.md#L501-L562) · [Cache warmer](https://github.com/Anil-matcha/suparagent/blob/c0cd2b155859b3c421c9592f017376df7d71f696/backend/app/services/cache_keep_warm.py#L1-L39) · [Defaults](https://github.com/Anil-matcha/suparagent/blob/c0cd2b155859b3c421c9592f017376df7d71f696/backend/app/core/config.py#L243-L247)
- **For Raphie.** Borrow exact fold boundaries, stable replay, visible recall provenance, and an inexpensive failure fallback. Automatic capture deserves its own evaluation and controls. Leave periodic cache warming off unless measured savings justify the extra calls and chat traffic. [Compaction policy](https://github.com/Anil-matcha/suparagent/blob/c0cd2b155859b3c421c9592f017376df7d71f696/docs/MEMORY.md#L178-L225) · [Cache warmer](https://github.com/Anil-matcha/suparagent/blob/c0cd2b155859b3c421c9592f017376df7d71f696/backend/app/services/cache_keep_warm.py#L1-L39)

## Composio Open Dot

- **Product and maturity.** Public 0.1.0 macOS-oriented Electron app with a local Next.js server. GitHub reported **738 stars** and a September 30 default-branch commit. The README calls it open source, but the inspected tree has no project license file and the package manifest declares no license. Treat it as publicly readable source with reuse terms unconfirmed. [Repository](https://github.com/composio-community/open-dot/tree/f838e17cf5c3a88ade5ceea54680a8145d048c1d) · [Package manifest](https://github.com/composio-community/open-dot/blob/f838e17cf5c3a88ade5ceea54680a8145d048c1d/package.json#L1-L14) · [Desktop setup](https://github.com/composio-community/open-dot/blob/f838e17cf5c3a88ade5ceea54680a8145d048c1d/README.md#L3-L26)
- **Chat and work.** The sidebar supports many chats per dot, with voice task continuation in the selected chat. A local cron callback and Composio app events enqueue work into separate routine or trigger chats. A routine reuses its history. An event run starts from a fresh model context. The app serializes ordinary tool-loop runs per dot in an in-process queue. `message_dot` waits for a bounded peer consultation. `send_update` posts into the active route and emits a notification. These mechanisms support background updates while the desktop process is running, with no durable concurrent work ledger visible in the inspected loop. [Chat selection](https://github.com/composio-community/open-dot/blob/f838e17cf5c3a88ade5ceea54680a8145d048c1d/src/components/Chat.tsx#L40-L71) · [Cron](https://github.com/composio-community/open-dot/blob/f838e17cf5c3a88ade5ceea54680a8145d048c1d/src/server/scheduler.ts#L9-L36) · [Queue and routing](https://github.com/composio-community/open-dot/blob/f838e17cf5c3a88ade5ceea54680a8145d048c1d/src/server/agent/runtime.ts#L43-L105) · [Run guard](https://github.com/composio-community/open-dot/blob/f838e17cf5c3a88ade5ceea54680a8145d048c1d/src/server/agent/runtime.ts#L195-L220) · [Model reset](https://github.com/composio-community/open-dot/blob/f838e17cf5c3a88ade5ceea54680a8145d048c1d/src/server/agent/runtime.ts#L248-L265) · [Update and consult tools](https://github.com/composio-community/open-dot/blob/f838e17cf5c3a88ade5ceea54680a8145d048c1d/src/server/agent/tools.ts#L211-L238)
- **Context and cost.** OpenAI uses stored Responses chained via `previous_response_id` with automatic truncation. Certain broken chains are rebuilt from user/dot text in the most recent 40 transcript records. OpenRouter replays reduced tool and message items and drops oldest history at user-message boundaries above 80 items or 160,000 serialized characters, provided another user boundary exists. This is a sliding replay cutoff with no written summary, and the newest exchange can exceed the limits alone. I found no prompt-cache policy in the request path. OpenAI's API guide explains that chaining IDs still bills prior input tokens. ## Shafreeck opendots and Morphz

- **Product and maturity.** Single-owner, local Node 24 web host in front of a pinned Morphz 0.1.3 Rust runtime. GitHub reported **0 stars** for the wrapper and an October 1 default-branch commit. The repository is a reconstruction of unrecovered source history. The wrapper's license review says its own files have no selected open-source license, while Morphz's original runtime code is generally Apache-2.0 with listed exceptions. The authors show actual runtime recovery and concurrency with a deterministic loopback provider, with real-model and graphical/device acceptance still open. - **Chat and concurrent work.** The wrapper keeps an exact Agent/Context/Session binding in SQLite for its foreground chat and uses native Objectives for parallel work. Task details show progress, results, and resources. Follow-ups address the selected Objective, current generation and, for a response to a wait, its request ID. The reconstructed code allows an explicitly acknowledged exact wait response when question text is unavailable. A stable command key lets recovery look up the original receipt after a lost response. Native timers handle absolute and fixed intervals. The wrapper materializes one future daily/weekly calendar occurrence at a time and records the exact UTC request for reconciliation. Its in-app inbox is durable. I found no verified external push delivery. The model derives or revises Frames with source references and retires processed observations through validated transactions. Oversized inputs can be reduced to a batch of observations. The current session gets priority, and other sessions may be rendered as metadata or omitted as the budget shrinks. ## Lessons for Raphie

1. **Start by testing the compaction policy already on this branch.** It starts a background summary by 64,000 working tokens on large windows, reserves up to 16,384 tokens, and retains up to 20,000 recent tokens verbatim. The summary carries commitments, open requests, preferences and decisions, entities, exact facts, and the immediate lead-in. The hook memoizes a finished summary and falls back to Pi on failure. Use Suparagent's durable, observable fold as a benchmark for verifying transcript integrity, retained boundaries, and provenance. Measure pre/post input, cached input, summary cost, and blocking time. Include a repeated-compaction case, an oversized tool result and an owner correction after an older summary was written. [Raphie policy](../../packages/runtime/src/domains/conversations/domain/compaction.ts) · [Summary hook](../../packages/runtime/src/domains/conversations/infrastructure/chat-summary.ts) · [Existing trace fields](../../packages/runtime/src/domains/conversations/infrastructure/pi-execution-traces.ts#L69-L76) · [Suparagent fold](https://github.com/Anil-matcha/suparagent/blob/c0cd2b155859b3c421c9592f017376df7d71f696/backend/app/services/context_compaction.py#L221-L273)
2. **Recover exact facts from the transcript when the summary is thin.** Start with a bounded read/search tool over the current chat's compacted region. Return dated snippets and stable message IDs so the bot can quote the source. A small SQLite lexical search is a reasonable first implementation. Explicit quotes should resolve directly even when the text is older than the model's tail. For rewind, keep the marker and filter rewound statements out of ordinary active-context recall while preserving recorded external effects. Respect channel membership and audience when delivering results. Add a short automatic recall pass only if evaluations show misses persist. [Raphie quote and rewind semantics](../../CONTEXT.md#language) · [Suparagent recall limits and provenance](https://github.com/Anil-matcha/suparagent/blob/c0cd2b155859b3c421c9592f017376df7d71f696/docs/MEMORY.md#L114-L160) · [Morphz exact evidence reads](https://morphz.ai/en/docs/contexts-and-recall#recall)
3. **Keep the work item authoritative.** Use one durable work item per continuing responsibility and reuse its background session while it is open. Treat a one-turn request as ordinary chat. Give the foreground turn a small projection of open work items with stable ID, title, status, what is awaited, next wake, and latest result. Load detailed notes or artifacts only for the relevant item. Use a typed, idempotent outcome keyed to the work item and run so retries cannot post duplicates or apply stale outcomes. Quote the original owner request when posting results. Keep item actions on the Work page and in chat commands. A follow-up addressed to an older run should require a current target. [Raphie work item and quote semantics](../../CONTEXT.md#language) · [Digger's reusable worker](https://github.com/diggerhq/opendots/blob/fbdf673f2648507cf4710ed00d480ba787f4e3a8/src/lib/topics/service.ts#L72-L155) · [Digger outcome routing](https://github.com/diggerhq/opendots/blob/fbdf673f2648507cf4710ed00d480ba787f4e3a8/docs/development.md#L48-L65) · [Morphz wrapper's exact follow-up](https://github.com/shafreeck/opendots/blob/dba64e3ba5c31d7768f551fa92a6398396e9da8a/src/objective-input.ts#L29-L53)
4. **Give the scheduler and delivery explicit state.** Link occurrences to their work item and preserve the difference between a scheduled time, an admitted run, a completed run, and a delivered result. Bound catch-up, skip overlap, reserve admission for owner turns, and record uncertain effects for review. Make pause, skip, and completion visible without filling chat with routine progress. Start with existing scheduling and permission controls, and treat event-triggered monitoring as a later capability with explicit sources and notification rules. [Raphie execution guarantees](../../apps/docs/src/content/docs/architecture/overview.mdx#design-rules) · [Suparagent scheduling and recovery](https://github.com/Anil-matcha/suparagent/blob/c0cd2b155859b3c421c9592f017376df7d71f696/docs/ROUTINES.md#L49-L74) · [OpenBot repeat limits](https://github.com/CopilotKit/OpenBot/blob/5ff641de36cb5e459ed01637106912b4b5ba416d/docs/routines.md#L107-L161) · [Morphz admission evidence](https://github.com/shafreeck/opendots/blob/dba64e3ba5c31d7768f551fa92a6398396e9da8a/docs/SOURCE_AUDIT.md#L13-L17)
5. **Keep memory evidence corrigible and measure prompt reuse.** Preserve evidence sources, time and correction history. Start with explicit retention and scoped retrieval. If passive capture is warranted, evaluate it first on eligible private turns and give the owner a way to inspect and revise its results. Keep instructions, owner profile and stable tool definitions early in model input. Place volatile recall and work status later where provider format allows. Compare the cache-read share, effective input cost, latency and recall accuracy on the same long-chat workload. That measures the benefit without copying Suparagent's synthetic cache-warming turns or adopting a provider-specific opaque summary format as Raphie's canonical state.
