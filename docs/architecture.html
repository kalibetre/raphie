Discord / target

Shared interface planned

The channel adapter verifies identity, resolves a conversation binding, and submits a message. It renders replies and explicit approval controls; inspection commands are not required.

Clients observe work.

Closing a browser, desktop window, or CLI viewer does not cancel runtime-owned execution.

Channels present work.

Discord and Telegram use native messages and controls. They do not need an inspector to be complete.

Sessions outlive interfaces.

UUID identity belongs to the conversation. Linking it to another channel is a later, explicit feature.

03

Follow a Discord turn

Target flow

Select a stage. This is a conceptual trace, not live agent telemetry.

Admission is not completion.

The adapter verifies the configured owner and external conversation. Channel ingress resolves its binding, authorizes the request, and admits a turn durably. A repeated request returns the same receipt; different content with the same ID is a conflict.

external event → authorized binding → session UUID → accepted turn receipt

The same request identity and content return the original receipt. A retry does not create a second turn. Different content under that identity is rejected as a conflict.

04

Migrate in working slices

All four slices planned

The existing prototype remains usable between slices. No database reset, transcript copy, or new message broker.

Next implementation slice

A small, shared application interface

Use public session UUIDs and trusted actor context for conversation submission, session reads, and approval decisions. Keep existing endpoints as compatibility adapters.

Proof of completion

Without a web process: a Discord fixture sends a message, requests approval, executes the exact approved tool call, and receives its reply. A stale second approval cannot repeat the action.

Planned / slice 02

Separate identity from destination

Move Discord associations into channel bindings. Backfill existing associations and capture the intended reply destination on each admitted turn. Keep the same sessions and deduplication identities.

Proof of completion

Restarts and duplicate events preserve the same binding, turn, and destination. Another thread cannot read its history or decide its approvals. No session-linking feature is introduced.

Planned / slice 03

Make delivery its own responsibility

Conversation and approval operations record intent. A scoped channel worker renders and persists a delivery plan before sending independently tracked chunks, cards, attachments, and edits.

Proof of completion

Kill a worker after one chunk: recovery does not silently duplicate it or lose the remaining plan. An uncertain notification never causes a completed tool action to run again.

Planned / slice 04

Read only what a client needs

Replace whole-workspace snapshots incrementally with summaries, paged history, pending approvals, structured phases, session observations, and optional inspection queries.

Proof of completion

An HTTP client fixture lists a session, sends a message, observes output, and decides an approval with the web app absent. Slow viewers and reconnects do not interrupt execution.

Later: desktop, CLI, and Telegram

Clients reuse the runtime interface. A local desktop package must attach to the existing execution owner for its data directory. Telegram adds its own identity verification and rendering. Remote clients require authenticated runtime access before changing loopback exposure.

Later: continue a session across channels

Introduce explicit, ownership-checked link/unlink operations and destination selection, with a policy for history disclosure. No automatic account matching, transcript copying, or broadcast to every connected destination.

05

What the migration must preserve

Durable identity

Keep session UUIDs, turn and approval IDs, request deduplication, existing history, and original deadlines.

Honest uncertainty

Remote delivery is not exactly-once. Preserve uncertain outcomes and reconcile before blindly resending or rerunning effects.

One execution owner

Clients do not open the durable store. Local-host browser checks are not a substitute for authenticated remote-client access.

Measured capacity

100+ agents is a workload goal, not a measured capacity claim. Benchmark active agents, sandboxes, subscriptions, and storage separately.
